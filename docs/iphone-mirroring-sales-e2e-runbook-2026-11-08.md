# 销售扫码页 iPhone 端到端测试操作手册（2026-11-08）

> 面向其他 AI / 工程同学：按这份文档，在**真实 iPhone（iPhone Mirroring）**上，
> 用手机相册里的二维码代替扫一扫，完成销售扫码页的真实写库测试。
>
> ⚠️ 测试会写**生产 Base**，必须拿到业务负责人的当次明确授权；没有授权只做到「提交前」为止。
>
> 销售数据来源：[销售数据](https://scnzoiwpgxik.feishu.cn/base/QrXlbwXMLaJ2TNsxSfFcIA3rnwh?table=tblXmhAoryDtUU7z)

## 一、环境与前提

| 项 | 要求 |
|---|---|
| 手机 | iPhone；已开启 iPhone Mirroring 并连接 Mac |
| Mac | 已运行「iPhone Mirroring」；终端有屏幕录制 / 辅助功能权限 |
| 工具 | `osascript`、`screencapture`、`cliclick`、`ffmpeg` |
| App | 飞书；已登录工作台（`邯美工作台`） |
| Base | 生产 Base 可写；测试前确认当前操作的是生产还是测试 Base |
| 二维码 | 对应货品的「标签二维码」已存入手机「照片」相册 |
| 授权 | 允许真实提交并生成销售单 |

## 二、获取镜像窗口坐标

```bash
osascript -e 'tell application "System Events" to tell process "iPhone Mirroring" to get {position of window 1, size of window 1}'
```

典型：

```text
905, 33, 361, 795
```

截图：

```bash
screencapture -x -R905,33,361,795 /tmp/iphone.png
```

截图是 **2 倍图**（约 722×1590），坐标换算：

```text
Mac x = 窗口 x + 手机截图 x / 2
Mac y = 窗口 y + 手机截图 y / 2
```

点击：

```bash
cliclick c:<Mac x>,<Mac y>
```

## 三、销售扫码页操作路径

```text
工作台 → 销售 → 鞋类
→ 扫一扫
→ 弹出「iPhone camera is not available from Mac」→ OK
→ 底部「相册」
→ 在「最近项目」选对应二维码
→ 进入「XXXX · 扫码」货品页
```

⚠️ 不要走 Photos 的 Live Text；正确入口是**扫码页自己的「相册」按钮**。

## 四、货品页填写

1. **选尺码**
   - 点击尺码卡片中心；
   - **确认 radio 真正出现蓝色实心选中态**；
   - 只看到蓝色聚焦环不算选中。

2. **填实收金额**
   - 点「实收金额」输入框；
   - 输入金额；
   - 键盘弹出后点右下角 ✓ 收起。

3. **提交**
   - 点「提交」；
   - 未选尺码/未填金额时，浏览器原生 `required` 会拦住并显示「选择一个选项」；
   - 此时请求没有发出，零写入；补选后重新点提交。

## 五、资金页

货品页提交后进入「总金额」页，**此时还没有写销售单**。

- 校验：全付时，**每件实收合计必须等于收款行合计**；
- 不等 ⇒ 后端返回 `amount_mismatch`，零写入；
- 多笔支付：
  1. 点「+ 再加一种付款方式」；
  2. 每行选支付方式、填金额；
  3. 合计必须等于总金额；
- 赠品：
  - `cliclick` 不能直接输入中文；
  - 用剪贴板：

```bash
printf '鞋油、鞋垫' | pbcopy
# 点击赠品输入框后
osascript -e 'tell application "System Events" to keystroke "v" using command down'
```

然后点「提交」。

## 六、销售单号与写库时机

```text
货品页提交：
  校验尺码/金额
  写入本地会话草稿
  从本地缓存分配销售单号
  渲染资金页（此时 Base 无销售单）

资金页提交：
  submitSale 异步任务
  → 创建销售主表
  → 批量写销售明细 / 交易明细 / 库存流水
  → 实时库存扣减
  → 主表收口（总金额 + 写入状态）
```

## 七、失败排查

### 7.1 页面提示「提交失败，请刷新后重试」

先看后台日志有没有：

```text
scan.page.login_redirect
→ 302 /start
```

这通常是**扫码页停留太久，登录会话过期**，不是金额/尺码校验。

处置：

```text
不回写、不重试旧页
→ 重新扫码
→ 快速填完并提交
```

### 7.2 页面提示金额校验

```text
scan.sale.amount_mismatch
```

核对：

```text
每件实收合计 == 收款行合计
```

不等就改金额，不要强行提交。

### 7.3 尺码选不上

```text
原生 required 校验
→ 确认点的是尺码卡片中心
→ 确认 radio 蓝色实心
→ 再点提交
```

### 8.3 数据缺口

16–24 目前多数只有「销售原文」：

```text
编号 / 尺码 / 支付方式 / 金额/双 为空
```

所以：

```text
手工执行：可以按原文走
自动断言：先补字段，否则只能核对原文与结果
18–21：没有原文，直接跳过
```

### 8.4 新增收款方式

2026-11-09 生产「支付方式管理」新增：

```text
微信红包
农业银行
```

「微信红包」当前可用于退款；「农业银行」当前不可用于退款。
售后下拉要在刷新页面/重开弹窗后才更新。

## 九、成功判据

手机页面出现：

```text
数据提交成功，后台自动写入
```

后台确认：

```text
scan.sale.submitted
v1.sale.posted（write_status=成功）
scan.sale.async.done（status=succeeded）
```

Base 确认：

```text
销售主表：写入状态=成功、总金额正确、待交付/需交付正确
销售明细：编号/尺码/实收金额正确
交易明细：金额/支付方式/钱款状态正确（分笔支付应为多行）
库存流水：对应库存键减少
实时库存：对应尺码库存减少或记录删除
```
