## 1. 布局（未来合并后）

```
① 第一个卡片： 销售 · 补货 · 库存 · 退货        ＋「继续扫下一个」
② 接下来：     货品信息卡（货号 · 颜色 · 品类 · 类别 · 价格）
③ 再往后：     各领域对应的「信息页」
```

- ⭐ **排序要改成**：**库存 · 销售 · 补货 · 退货 · 扫一扫**
- **默认仍是销售页** ✓（改了排序也要保持默认落销售）
- 第一个卡片里的那格写法是 `销售 · 补货 · 库存 · 退货`（**四个领域**）＋「**继续扫下一个**」。

## 2. 为什么这四个都归到「扫一扫」

它们**都需要把「扫一扫」作为数据录入的入口** ✓。
（与姊妹篇那两条判据并行：**发生频次高** ＋ **符合真实业务链路**；低频的（库存手工调整 / 换季调整）
走独立页，打印标签走「货品」模块。）

## 3. 库存页

- **可录入范围**：**男鞋 38–48 / 女鞋 34–43** ✓
- 尺码分**普通码 / 特殊码**：
  - **普通码：不论有货没货都展示** ✓
  - **特殊码：有货才展示** ✓
- **补货页里，特殊码没货时默认不勾选** ✓
- 库存页展示**三个维度**：**样品 · 门盒 · 仓库库存**（用来查**单双**库存 ✓）

## 4. 销售页

- 支持**一单多个商品** ✓、**一单多种收款方式** ✓
- 走**异步查询** ✓
- 流程**三个页面**：**货品页 → 资金页 → 提交成功页** ✓

## 5. 补货页 / 退货页（本质同一套逻辑）

- **退货**：按该货号下**实际存在的尺码和数量**（**取实时库存的数据**）生成退货单 ✓
- **补货**：支持**一键自动补充所缺的普通码** ✓；数量**默认 1** 且**可编辑** ✓

## 6. 🔴 大逻辑调整（她说是「今天讨论的核心重中之重」）

- 像销售一样**一单多个商品** ⇒ **一次补货单 / 退货单也要支持多个货品** ✓
- 参照物是她给的那张**申请单**：**一张单里申请多个货品** ✓

## 7. 异步

- **补货 / 销售 / 退货都是异步** ✓
- **前端先提示「单号已创建」** ✓，**后端写表异步进行** ✓
