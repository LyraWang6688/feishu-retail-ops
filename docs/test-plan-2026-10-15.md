## 2.5 七条判据（每条：怎么测 + 什么算红）

| # | 判据 | 怎么测 | 红的样子 |
|---|---|---|---|
| 1 | **该写的都写了** | 2.4 的逐字段表；每条链路每个字段都核一遍 | 基准表里有、落库为空/值不对 ✗ |
| 2 | 🔴 **飞书自动字段一行不写** | 核"创建时间 / 更新时间 / 到货日 / 验收人"这类列：**值只可能来自飞书** | 代码写进去（同一次请求里被覆盖 / 手动值）✗；⭐ 已知**唯一例外 = 收款明细·「收款日」**（人工列，代码写 ✓，见基准表第 5 节） |
| 3 | **幂等：重复/并发只写一次** | 同一次提交**连点 3 次**（或同一 `submitKey` 重放）；再**并发**发两次 | 多出第二张主表 / 第二行明细 / 第二次扣库存 ✗（应：**复用同一条**，日志里 `reused:true`） |
| 4 | **账对** | ① 明细 Σ（实收/数量） **= 主表金额**；② 收款明细 Σ **= 实收**；③ **拆行分摊不许翻倍**（拆 N 行 ⇒ 各行金额之和 = 原值） | 差 1 分也算 ✗；拆行后被乘了 N 倍 ✗ |
| 5 | **不动不该动的** | ① **配品**那一行 **不动库存** ✗；② **现货**行的库存动作只发生**一次**；③ **退货每行 ≤ 该码实时库存** | 配品扣了库存 ✗；退货超出实时库存 ✗ |
| 6 | **异步：先给单号 + 失败如实可见** | 销售链路（`SCAN_SALE_ASYNC_WRITE_ENABLED` 默认开）：点按钮 ⇒ **先回单号**；后台写明细/库存；人为让后台失败一次 | 卡住不给单号 ✗；失败被吞（页面/日志说成功）✗；**丢了不合格的行** ✗ |
| 7 | **可追溯：日志带关联键** | 拿这单的 `order_no` grep 日志：`task_id` / `order_no` / `sales_entry_record_id`（采购侧 `batch_no` / `purchase_batch_record_id`） | 只有卡片日志、没有写库日志 ✗（她 2026-10-07 拍板"日志改下吧"就是这条） |

# 三、对账口径（她一眼看"今天写的单有没有异常"）

**跑法**：按当天的 `order_no` / `batch_no` / 日期过滤日志（结构化 JSON，可 grep），或看工作台列表。

| 看什么 | 怎么看 | 正常 | 异常（要查） |
|---|---|---|---|
| **今天写了几单** | `v1.sale.posted` 条数（销售）· `purchase.webhook.accepted` / 建批次日志（补货退货） | 条数 = 她今天操作次数 | 条数**多于**操作次数 ⇒ 幂等没中 ✗ |
| **行数与金额** | 每单：明细行数 = 她选的双数；**明细 Σ = 主表金额**；**收款 Σ = 实收** | 相等 | 不等（差一分也要看）✗ |
| **幂等命中** | 日志里 `reused:true` / "已提交过" | 连点时**只有 1 条真正建单** | 出现 2 条建单 ✗ |
| **失败数** | `*.failed` / `sale_partial_failed` / `scan.purchase_return.shortfall` / `inventory.change.*failed*` | 0（有也要有**人话**出口） | 有失败但页面上说成功 ✗（最坏）；失败没有出口 ✗ |
| **该少到的** | `scan.purchase_return.shortfall`（退货少到）· 验收的"实际 < 申请" | 记录与实物一致 | 实物 1 双、账面 2 双 ✗ |
| **库存对得上** | 该款现在实时库存 = 昨天 + 进货 − 卖出 − 退货 ± 调整 | 一致 | 对不上 ⇒ 按 `order_no` 反查那一单（判据 7） |

**一句话版**（贴群里用）：
> 「今天 **N 单**：明细/收款金额**对得上** ☐；连点**没有多写** ☐；失败 **0 条**（或都有出口）☐；
>  退货少到 **K 条**（与实物一致 ☐）；库存对得上 ☐。」——有任何一项 ☐ 打不上，就带**单号**来找我们查。
