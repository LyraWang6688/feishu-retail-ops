# 冻结件「整份 sha」判据的形状问题（2026-10-16 晚）

> ⭐ 一句话：**「钉整份文件的 sha（或整份文件逐字节）」这种判据，天生会被【后来任何合法改动】作废** ✗
> ⇒ ⭐ **正确形状 = 「钉基线 ＋ 改基线必须留台账」** ✓

## 1. 起因（当晚真实发生）

| 时刻 | 事情 |
|---|---|
| 2026-10-16 21:00 前后 | PR **#763**（`task-62` 货 / 钱分离 · 阶段二）拿到业务负责人**明确批准**「**允许改冻结文件**」（**一次性、只为本卡**），**合法地**改了 `server/src/services/scanWriteService.js`：sha `199551e1…35ca`（1699 行）⇒ `49772bda…2c12`（1770 行），并在 `test/scanWriteServiceFrozen.test.js` 留了**解冻台账** ✓ |
| 同一时刻 | 它把**另一张卡**的判据撞红 ✗：`server/test/purchaseReturnMultiItem.test.js` 的 ⭐ **AC-RS6** |

`AC-RS6` 是 `task-64`（退货一单多货 · PR **#761**）写的，实现方式是 ⭐ **钉「整份文件的 sha == `199551e1…`」** ✗。
⇒ 于是它**把 #763 那次【合法】改动判定为红** ✗ —— 它想测的其实是「**我这一卡没碰它**」✓，
写出来的却是「**这个文件永远不变**」✗。

⚠️ **时序让它更隐蔽**：#761 是**后来才合进 main** 的 ⇒ #763 的作者**写的时候根本看不见那个文件**（本地绿、合并后才红）。
⇒ **不是谁的错，是判据形状的错** ✗。

## 2. 要落的规律

⭐ **「钉整份文件的 sha（或整份文件逐字节）」这种判据，天生会被【后来任何合法改动】作废** ✗
⇒ ⭐ **正确形状 = 「钉基线 ＋ 改基线必须留台账」** ✓

**现成范例**：`server/test/scanWriteServiceFrozen.test.js` 的 ⭐ **AC-FRZ4 解冻台账** —— 文件头**逐字**写
「**改前 sha → 改后 sha → 依据**」，并且 ⭐ **「只改常量、不写台账 ⇒ 红」** ✓（防"悄悄重设基线" ✗）。

## 3. 推论（三条可执行）

① **要防"没人偷偷改"** ⇒ 用**台账式哨兵**（改基线必须留一行逐字依据 ✓）—— **别用裸 sha** ✗。

② **改了被多张卡引用的文件（尤其是冻结件）** ⇒ ⭐ **必须全仓搜旧 sha** ✓：

```bash
grep -rn "199551e1" server/test/     # 旧 sha 取前 8 位即可（同时搜 server/src/ 更稳）
```

把**每一处命中都成对迁移** ✓，**别只改自己那张卡的** ✗。
⚠️ 当晚实测：那份基线在 `server/` 里共有 **7 份副本**（7 个测试文件各钉一份）—— **漏一份就红一条** ✗。

③ **判据的语义要写清**：它测的是 ⭐ **「这一卡没越过那条基线」** ✓，而不是 **「文件永远不变」** ✗。

## 4. 当晚的处置（对照）

- #763 那次解冻：**成对迁移**了**全部 7 处**副本（改前逐字 → 改后逐字 → 依据，逐处写在注释里 ✓）。
- ⚠️ 教训：**解冻之后必须重新 `git fetch` / merge 一次最新 `main` 再跑一遍** ——
  副本会随**别人合进来的 PR** 继续增殖（#761 就是在 push 之后才合的）⇒ **本地绿 ≠ CI 绿** ✓。
