# 待办：到货核对卡片改成「表单填写 + 提交」触发（业务负责人 2026-10-07 深夜定）

> 她的原话（逐字）：
> 「我们的消息卡片是否支持**输入一段文字**？就比如说，我们对于采购这一块，也是像销售一样
>  发到群里一个卡片，**等到货之后，请在卡片里填写实际到货情况**。也就是给到用户卡片，
>  **用户填写内容之后，再点击提交**。以这个来作为**触发后续的到货验收**」
> 她已确认：「好的，派人做吧～」

## 已核实的可行性（官方文档，curl 实查）
- **输入框组件**官方原文：「在卡片进行**内容收集**的场景下…可以使用输入框组件，实现简单的**文本内容收集**」
  → `https://open.feishu.cn/document/feishu-cards/card-components/interactive-components/input.md?lang=zh-CN`
- ⚠️ **必须内嵌进「表单容器」**，与按钮一起；输入框需 **飞书 V6.8+**（低版本显示降级占位，可用 `fallback`）
- 回调字段：**`form_value`**（对象：表单项 name → 值，官方示例 `"form_value": {"Input_lf4fmxwfrd9": "1234"}`）；
  不在表单里的输入框用 `input_value`
  → `https://open.feishu.cn/document/feishu-cards/card-callback-communication.md?lang=zh-CN`
- ⚠️ 表单内每个交互组件必须有**唯一 `name`**（否则飞书报错 200530）

## 要做的
1. **采购到货核对卡片**（既有那张，在她说到货之后发出的）上增加：
   · 「**实际到货情况**」**多行文本输入框**（name 例：`actual_arrival`，必填、可配 placeholder）
   · 【**提交**】按钮（与输入框同在**表单容器**里）
2. ⭐ **提交 = 触发到货验收**：把 `form_value.actual_arrival` 的文字**当作"她在话题里说的那句话"**，
   直接喂给**既有那条**到货验收解析（`parseArrivalReconciliation` → 差异比对 → 出确认结果/入库计划），
   **不要另造一套解析**。
3. ⭐ **与今天定的口径一致**：主触发是按钮/表单提交；**在话题里说话也可以照旧触发**（除非她另说）。
4. **提交后**：把卡片 patch 成"已提交/已核对"状态，避免重复提交；**幂等**（同一提交不重复入库）。
5. **配置先行**：输入框 name/label/placeholder/必填文案/提交按钮文案全进 `config/`。
6. ⚠️ 兜底：客户端 < V6.8 ⇒ 输入框不可用 ⇒ 卡片要**仍能让她在话题里说**（保留文字入口，别把老路堵死）。
7. 测试：① 提交带文字 → 走既有解析 → 出结果/入库（与"在话题里说同一句"结果**逐字一致**）
   ② 空提交/未填 → 明确提示、不写库 ③ 重复提交不重复入库 ④ 老客户端降级时文字入口仍可用
   ⑤ 卡片表单结构含唯一 name、输入框在表单容器内（结构断言）
