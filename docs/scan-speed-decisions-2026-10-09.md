# 扫码页提速与缺省领域（业务负责人 2026-10-09 定）

## 1. 尺码段**写进配置**（不再每次查「尺码管理」）
- **A（男）= 38–48** · **B（女）= 34–43** ⇒ 进 `config`（不是散在逻辑里）
- ⭐ 同时加一条**一致性保险**：定期（或启动时）拿**配置**与**「尺码管理」表**比对，
  不一致就记一条 **warn**（例如表里加了 49 码而配置没跟） ⇒ **快 + 不会悄悄错**
- 缺码判定 = 该类别（编号第 3 段）的**配置段**里，库存为 0 的码

## 2. 单价：**选项 2**（她 2026-10-09 选定）
- **单价留在「货品信息」（唯一真源）**；把「货品信息」**整表进内存索引（按编号）** ⇒ 扫码 **0 次飞书调用**
- ❌ 不采用"在「实时库存」加单价列"（会造成同一款多份单价、改价要批量改、容易不一致）

## 3. 内存快照 vs 缓存（术语澄清，写给以后的自己）
| | 缓存（cache） | 内存快照（snapshot） |
| --- | --- | --- |
| 谁触发 | **有人请求**才存 | **服务器自己定期抄全表** |
| 存什么 | **某一次的结果**（编号 → 页面视图） | **整张表**（所有款） |
| 第一次快吗 | ❌ 第一次仍慢（要取数） | ✅ **第一次就快** |
| 过期 | TTL（45 秒） | 定期刷新 + **写操作立刻作废** |

⇒ 两者**互补**：快照解决"第一次慢"，缓存解决"同一款连扫更快"。
