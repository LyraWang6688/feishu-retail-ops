# 扫码页 · 销售 操作说明书

> 给她看的一页：**从扫码到提交**，每一步点哪里、什么可以不填。
> 时间：2026-10-12（这一版结构变了：**一单一笔是默认路径**）。

---

## 一、最常用：一单一笔（**两下**）

| 步骤 | 你做什么 | 会发生什么 |
|---|---|---|
| 1 | 用飞书扫鞋子标签上的码 | 打开这一款的页面（尺码分两组，见下） |
| 2 | 点一个**尺码**，然后点蓝色大按钮【**✅ 提交这一单（1 双）**】 | **一次就成单**：写销售单 + 明细 + （如果填了）收款 |

> 按钮上写着几双（`（1 双）`），点之前你就知道这一单里有几双。

## 二、一单多双（**要显式加**）

| 步骤 | 你做什么 |
|---|---|
| 1 | 扫第 1 双的码、点它的尺码 ⇒ 点【**➕ 还要加一双**】（这时**不要**点提交） |
| 2 | 扫第 2 双的码（可以换款式）、点它的尺码 ⇒ 再点【➕ 还要加一双】 |
| 3 | ……重复到全部加完 ⇒ 最后一次点【**✅ 提交这一单（N 双）**】 |

- 加单之后，顶部那条会写「**本单：N 双**」——随时知道已经加了几双 ✓
- **一单多双**就是"多扫几个码、每次点【➕ 还要加一双】，最后只提交一次"。
- 想重来：点【清空本单】（只清这一单的草稿，不会动已经提交过的单）。

## 三、什么可以不填（**都不影响成单**）

| 页面上的东西 | 必填？ | 说明 |
|---|---|---|
| 尺码 | ✅ 必选 | 不选尺码就没法加/提交 |
| **这一双的实收金额** | ⬜ 可以留空 | 留空 ⇒ 表里那一格也留空；**之后到工作台补** |
| **每件实收金额**（本单里一行一个） | ⬜ 可以留空 | 同上（页面上就写着这一句） |
| **备注（可不填）** | ⬜ 可以留空 | 整单合并成一条写进销售主表的「赠品」列（见"常见坑"②） |
| **付款情况** | ✅ 要选一档 | 默认「未付」；见第四节 |
| 收款方式 / 收款金额 | 看付款情况 | 「未付」可以不填；「全付」「部分付」要填 |

## 四、付款情况三档怎么选

| 档 | 什么时候选 | 系统会做什么 |
|---|---|---|
| **未付** | 钱还没收（或以后再补） | **不写**任何收款记录；这一单在工作台里显示"待补充"，之后用【补收款】补 |
| **部分付** | 收了一部分 | 按你填的收款行写收款记录；差额写一条【未收款】占位 + 填「实付多少」 |
| **全付** | 钱全收到了 | 收款合计必须等于每件实收合计；写好收款记录（状态：已收款） |

⚠️ 选了「全付」却**收款金额和每件实收都空着** ⇒ 系统会**拦住**并提示你（不会静默记一张"零元全付单"）。

## 五、提交之后你会看到什么

- 标题：**✅ 这一单提交好了**
- **销售单号**（例 `XSD-20261012-0001`）+ **共 N 双**
- 下一步：**要补实收 / 收款 ⇒ 去工作台「销售」那一页**
- 这一页**没有按钮**：刷新、误点都不会再提交一遍（已提交过的话会看到「✅ 这一单刚才已经交过了（单号 …）」——**那是同一单，不用理它**）。

## 六、常见坑

### ① 「提交这一单」以前有**两颗按钮**——已经修掉了

- 旧版：顶部那条「本单条」上也有一颗【提交这一单】，**它不带收款方式/金额**。
  如果你在下面的"销售"块里填了"全付 + 微信 280"，却按了**顶部那颗** ⇒
  **单子照样建出来，但收款明细一行都没有**（钱没记进去）。
- 现在：**一页只有一颗提交按钮**，就在"销售"块那唯一的表单里，
  **它永远带着收款方式/金额**——结构上不可能再丢钱 ✓
- 如果发现某张历史单的收款明细是空的（像上面那样），去
  **工作台 → 销售 → 找到那张单 →【补收款】**，填上方式+金额即可 ✓

### ② 「备注（可不填）」写进的是「赠品」那一列

- 页面上叫 **备注**，表里那一列叫 **赠品**（名字不一样，是同一样东西：这一单附带的说明）。
- 如果你觉得别扭，可以让技术把**列名改成「备注」**，或者把页面上那三个字改成「赠品」——
  两边统一就行（现在这种"名实不符"很容易让人找不到）。

### ③ 配品表单只在**「其他配品」里有数据**时才出现

- 一件配品都没建的时候，页面上**不会有**配品的下拉框/金额框（不留死下拉）。
- 你上次问"赠品在哪里"：**赠品不在配品里**——它在上面那条「备注（可不填）」，
  写进销售主表的「赠品」列。

### ④ 尺码分两组不是"让你多选"

- 上面那组是**现货**（样品 / 门盒里有），下面那组是**预订**（没有货）。
- 选哪一组就是"这一双是现货还是预订"：**现货 = 提交时立刻交付 + 扣库存**；
  **预订 = 不扣库存、以后交付**。
- 你**只需要点一个尺码**；一单一双就点提交，不用把尺码都点一遍。

## 七、页面上的东西分别写进哪张表（对照表）

| 页面上的东西 | 写进哪张表 · 哪一列 |
|---|---|
| 尺码（现货组/预订组选中的那一个） | **销售明细**：编号 / 配品 + 尺码 + 履约状态（现货=已交付、预订=未交付）+ 交易类型（现货 / 预订）+ **销售明细ID**（`销售单号-01`、`-02`…） |
| 现货行（提交时） | **实时库存**（卖掉的那一双减掉）+ **库存流水**（一条"销售减少"）+ 销售主表「库存状态」 |
| 这一双的实收金额 / 每件实收金额 | **销售明细**「实收金额」（留空 ⇒ 这一格留空，不写 0） |
| 备注（可不填） | **销售主表**「赠品」（整单合并成一条） |
| 付款情况 | **销售主表**「资金状态」+ 决定要不要写 **收款明细** |
| 收款方式 | **收款明细**「收款方式」（关联「收款方式管理」） |
| 收款金额 | **收款明细**「收款金额」 |
| 收款行（每行一笔） | **收款明细**：状态「已收款」+ 交易方向「收入」+ **收款日 = 你点提交那一刻** + **收款明细ID**（`销售单号-收款-01`、`-02`…） |
| 部分付的差额 | **收款明细** 一条【未收款】占位（方式留空、**也占一个号**） |
| 提交 | **销售主表**：销售单号 / 录单人 / 确认状态 / 赠品 / 交易类型 / 销售状态 / 资金状态 / 库存状态 |
| 【继续扫下一个】 / 领域切换 / 加单 / 清空本单 | **都不写业务表**（加单、清空只动本机草稿） |

## 八、一单一双 / 一单多双 的落表流水账

**一单一双**（默认路径）
1. 扫码 ⇒ 打开这一款页面（读「货品信息」+「实时库存」，**不写任何表**）
2. 点尺码 ⇒ 点【✅ 提交这一单（1 双）】
3. 服务端：**销售主表 1 行** ⇒ **销售明细 1 行** ⇒ （现货则）扣库存 + 库存流水 1 条 ⇒ （填了钱则）**收款明细 +1 行** ⇒ 本单归零、页面给"✅ 提交好了"

**一单多双**
1. 扫 A ⇒ 点尺码 ⇒【➕ 还要加一双】⇒ **本单：1 双**（此时**一张表都还没写**）
2. 扫 B ⇒ 点尺码 ⇒【➕ 还要加一双】⇒ **本单：2 双**
3. ……全部加完 ⇒ 点【✅ 提交这一单（2 双）】
4. 服务端：**销售主表 1 行** + **销售明细 2 行** + （现货行的）库存 + （填了钱的）收款明细 ⇒ 本单归零

> 一句话：**加单只动草稿，提交才写账**。所以加错了可以【清空本单】，不会留下脏数据。
