# ⭐ 开关的用法：什么时候该有开关、什么时候该直接开（业务负责人 2026-10-16 纠正）

## ⭐ 她的原话（逐字 · 起因：我第三次让她"开开关"）
> 「**我不明白了，为什么我们要改一个新东西的时候，你都让我开开关呀？
>  我们都改了，为什么还要开开关？我没明白这个意思。**」

## 🔴 我错在哪（认）
我把「**代码合进 main**」与「**线上行为改变**」严格分开是对的（因为**严禁自行部署**），
但**推演过头**了：⭐ **变成了"每一件新东西都留一个开关、每次都去问她"** ✗ ——
⭐ **已经验好的功能，缺省就该是【开】** ✓ **她没理解错，是我做拧了** ✓

## ⭐ 正确分法（以后照这个办 ✓）
| 类 | 判据 | 做法 |
|---|---|---|
| ⭐ **A 类 · 纯新增 / 纯修复**（**不改既有行为**） | 例：退货出图（修 bug）· 销售页也能弹扫码 · 五处扫一扫收口 | ⭐ **缺省就是开** ✓ **不用开关** ✗ **不用问她** ✓ |
| ⭐ **B 类 · 会改变既有行为** | 例：成功页极简（页面样子变）· 货/钱分离（建单/扣库存时机变）· 一单多货异步（提交即返回） | ⭐ **才要开关** ✓ ＋ ⭐ **才要她拍板** ✓ |

## ⭐ 两条配套纪律
1. ⭐ ⭐ **开关是【临时的】** ✗ —— ⭐ **验证通过一段时间后，必须"删掉开关、永远打开"** ✓
   （与仓库既有口径一致：⭐ **"退役 = 删代码，不是翻开关"** ✓）
   ⇒ ⭐ **不许把开关当永久配置留着** ✗（否则每次都要有人去开、还会漂 ✗）
2. ⭐ ⭐ **问她之前先自问一句**：⭐ **"这个开关，是我该顺手开的收尾动作，还是真的需要她拍板？"** ✓
   ⭐ **若功能已验、且她本来就要求过这个行为** ⇒ ⭐ **那是 A 类 ⇒ 别问** ✗
   ⭐ **只有当"开/不开都说得通、且影响她用起来的手感"** ⇒ ⭐ **才问** ✓

## ⭐ 落成这一条的直接效果
- ⭐ **A 类不留开关**（例：退货出图 —— 当时就没留 ✓ **正确** ✓）
- ⭐ **B 类的开关要在"上线后验收通过"就安排删除**（例：成功页极简 / 货钱分离 / 一单多货异步 ⇒
  一旦她确认线上效果 OK ⇒ **下一刀删开关、永远打开** ✓）
