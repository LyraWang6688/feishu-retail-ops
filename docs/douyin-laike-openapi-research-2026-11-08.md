## 2. 三条关键结论（先看这个）

### 2.1 豆包工作的连接器**搬不过来**，不是权限问题，是方向问题

- 豆包工作是 **MCP 客户端（host）**，不是 MCP 服务端。证据：草料官方文档教「在豆包工作中新建自定义连接器」，填 `传输类型 HTTP` + `服务器 URL` + OAuth 授权 —— 它能**装别人的 MCP**。
- 但它内置的「抖音生活服务 / 巨量本地推 / 千川 / 蝉妈妈 / TikTok」是**产品内置授权项**（操作是「搜插件 → 点连接 → 填 API Key」），**没有对外 MCP 地址**。
- 两个 host 之间不能互装：只有当能力以 `URL + 鉴权` 暴露成 server 时，任何 host 才能挂。
- ⇒ 想拿同一份数据，只能在豆包工作里用，或者走官方 OpenAPI 自己接。

### 2.2 给外部程序开的门是「生活服务 OpenAPI」

域名 `https://open.douyin.com`，覆盖门店 / 商品 / 订单 / 核销 / 评价等。这才是能写进本仓库、能被定时任务和飞书多维表格消费的那一层。

### 2.3 抖音开放平台的「MCP 服务广场」不能替代它

`https://open.douyin.com/sse`（SSE，`client_token` / `access_token` 鉴权，需申请开通、官方能力约 5 个工作日审批）确实可接，但官方能力清单是：**抖音视频搜索、图文搜索、获取抖音跳转链接、经营任务系统** + 第三方 MCP —— **不含来客经营数据**。别拿它当捷径。

## 3. 官方入驻流程（自研商家 / 品牌商）

来源：[自研商家入驻指南](https://developer.open-douyin.com/docs/resource/zh-CN/local-life/connect/developer/self-developed-merchant-guide)（文档更新 2025-12-02）

| # | 环节 | 谁做 | 耗时 | 观察点 |
|---|---|---|---|---|
| 1 | 入驻抖音来客 | ✅ 邯美已完成 | — | — |
| 2 | **来客里绑定开发者**：店铺管理 → 服务应用授权 → 商家自研服务 → 入驻开放平台 / 绑定开发者（手机号或邮箱） | 业务负责人，5 分钟 | 5 分钟 | 绑定成功后「操作」列出现「前往开发者平台」 |
| 3 | **创建「生活服务商家应用」**，拿 `APPID = ClientKey` / `AppSecret = ClientSecret` | 接手的 agent（可代点，需本人扫码） | 审核约 1 个工作日 | 应用详情页能看到 ClientKey / ClientSecret |
| 4 | **开通解决方案能力权限**：应用 → 解决方案 → 开通（整体开通 / 按能力开通） | 接手的 agent | 带「免审核」的当场开，其余人工审核 | 能力状态变「已开通」 |
| 5 | 自助化接入：开发信息 / IP 白名单（可选）/ SPI / Webhooks / 测试店铺 / 联调验收 / 压测验收 / 安全验收 / 上线 | 接手的 agent | 视验收 | 每一步平台有结构化表单 |

调用规则（已确认）：

- 域名统一 `https://open.douyin.com`，必须 HTTPS，路径以 `/` 结尾；
- 公共请求头 `access-token`（由 `/oauth/client_token/` 用 ClientKey/Secret 换，取 `data.access_token`）；
- POST 需 `content-type: application/json`；SPI 回调另有 `x-life-clientkey` / `x-life-sign` 签名。

## 4. 拟开发形态（建议，未实施）

一个**本机 MCP server**（Node.js，独立小进程，不塞进 `server/` 的 Express 业务）：

```
tool: laike.client_token     # 换 token（内部）
tool: laike.shop.query       # 门店
tool: laike.product.list     # 团购/套餐
tool: laike.order.list       # 订单（按时间窗）
tool: laike.verify.list      # 核销
tool: laike.review.list      # 评价
```

硬约束（建议写进实现）：

1. **只读优先**：核销、发券、改价一律不做（写入类先不进工具表）；
2. **凭据不进仓库、不进对话**：`ClientKey` / `ClientSecret` / 商家 token 写本机 env（`.env.example` 只登记键名），**业务负责人本人持有 secret**；
3. 产出对接既定形态：定时抓 → 写飞书多维表格（与现有 `feishu-retail-ops` 的表分开，避免污染唯一事实源）→ 日报/周报；
4. 失败不重试无限次：区分临时错误（网络/限流）与永久错误（权限/参数）。

## 5. 风险与未验证项（**别当成已确认**）

| 项 | 状态 | 说明 |
|---|---|---|
| 自研自用是否必须过「压测验收 / 安全验收」 | ❓ 未验证 | 文档写「逐项完成才能上线应用」；自研自用能否跳过，建了应用才知道。退路：浏览器抓来客后台报表 |
| 能取到哪些数据 | ❓ 取决于开通的解决方案 | 团购到店 / 预订 / 商品…各不同；**鞋店若只有代金券，商品维度会很薄** |
| 审核时效 | ⚠️ 不可控 | 应用约 1 工作日，能力审核可能更久 |
| 接口频率限制 | ❓ 未验证 | 见各接口文档 |
| 与现有团购券口径的对接 | ⚠️ 需对齐 | 收款口径见 `docs/douyin-voucher-payment-rules-2026-10-16.md`：差额按**面值**、收款明细按**平台结算款**、状态**待平台结算** —— 来客核销数据做对账时必须先对齐这三条，否则数字对不上 |

## 8. 分工与节奏（2026-11-08 更新：王颖「以后你就负责和抖音相关的开发」）

**归属**：抖音相关的**开发**（经营侧接入）由**本仓库的 agent** 负责推进与维护；业务口径（卖什么、要不要做）由王颖定。
**路线锁定**：官方**「自研商家（品牌商）」→ 生活服务 OpenAPI**（`https://open.douyin.com`）。另外两条（豆包内置连接器 / 开放平台 MCP 广场）**不再评估**（理由见第 2 节）。

### 8.1 阶段与闸门

| 阶段 | 谁 | 前置 | 产出 |
|---|---|---|---|
| **P0 资质** | **王颖**（约 10 分钟） | 来客已入驻 | ① 绑定开发者成功（「操作」列出现「前往开发者平台」）② 开放平台账号 / 企业认证 ③ secret 持有方式 |
| **P1 应用** | agent（她扫码） | P0 | 「生活服务商家应用」+ `ClientKey` / `ClientSecret`（审核约 1 工作日） |
| **P2 能力** | agent | P1 | 开通解决方案能力 —— **数据范围在这一步确定** |
| **P3 只读骨架** | agent | **不依赖 P1/P2**（假 env） | 本机只读 MCP server：6 个 tool 契约 + 单测；不写任何业务表 |
| **P4 联调** | agent | P2 + 凭据 | 真调 `open.douyin.com`（优先测试店铺），**只读** |
| **P5 落表** | agent | P4 | 定时抓 → **独立**飞书表 → 日报 / 周报 |

### 8.2 执行边界（agent 自约束）

1. **只读优先**：核销 / 发券 / 改价等写入类**不进第一版工具表**（第 4 节同款）；
2. **凭据**：只从本机 env 读，`.env.example` 只登记键名；`ClientSecret` 由王颖本人持有，**不进仓库、不进对话、不进日志**；
3. **不部署**：不做 `deploy_*` / `pm2 restart` / 改线上 `.env`；需要上线时先问她；
4. **不污染唯一事实源**：抖音数据写**独立**飞书表，不塞进 `feishu-retail-ops` 的业务 Base；
5. **失败分档**：临时错误（网络 / 限流）有限次退避，永久错误（权限 / 参数）不重试、只报清楚。

### 8.3 待王颖确认（阻塞 P1/P2，不阻塞 P3）

1. 来客里主要卖什么（代金券 / 套餐 / 只做曝光与私信）→ 决定开通哪个解决方案；
2. 是否已有「抖音开放平台」账号（需企业认证）；
3. `ClientSecret` 由谁持有。

> 未验证项（第 5 节）继续标 ❓：压测 / 安全验收能否跳过、能取到哪些数据、频率限制 —— **建了应用才知道**，别提前承诺。
