## 4. 「到货日」到底是不是飞书自动字段（**读生产真表**的结论）

**结论：是"飞书自动填写"的字段，但它不是一个 1001+ 的自动类型字段。**

- 读法（按纪律，**用项目代码**、不用飞书 CLI）：`server/scripts/list-v1-fields.js` →
  `V1BitableGateway.listFields('purchaseArrival')` → 官方 SDK `bitable.appTableField.list`。
  本机按纪律没有生产凭证，所以**在服务器上**跑同一个脚本读生产 Base。
- 生产「采购到货」（`tblvLOXKESNTbZ7v`，8 个字段）实测：

  | 字段 | 类型 | 结论 |
  |---|---|---|
  | **到货日** | `type: 5` / `ui_type: DateTime` / **`property.auto_fill: true`** / `is_primary: true` | **飞书自动填写当天** → **代码不写** |
  | 创建时间 | `type: 1001` CreatedTime | 飞书自动 |
  | 更新时间 | `type: 1002` ModifiedTime | 飞书自动 |
  | 图片 / 验收原话 / 报货批次号 / 验收人 / 确认状态 | Attachment / Text / SingleLink / User / SingleSelect | 普通字段 |

- **行为验证**（在**测试 Base** 上真跑一次项目代码）：只写「验收原话」新建一条到货记录，
  飞书把「到货日」自动填成了**当天**（测试 Base 的同一个字段同样是 `auto_fill: true`）。
  ⇒ 「代码不写它、由飞书自动生成」这条在她的表上**成立**。
- ⇒ 口径落地：**代码一个字都不写「到货日」**；测试里断言 create 的取值里没有这个键
  （用例「点「是」①」）。

## 8. 没做到 / 需要她确认的

1. **「到货日」不是 1001+ 的自动类型字段，而是"自动填写"的日期字段**。
   结论上不影响她的口径（新建记录时飞书确实自己填当天，实测见第 7 节），但**这个区别要告诉她**：
   那一列在飞书里**是可以手填的**（她自己在表里点开记录就能改），
   "自动"靠的是字段设置里的 `auto_fill`。
2. **没有做"入库之后还能改"**：入库点只有「是」这一个，入库之后再说的话不动任何表。
3. **模型是桩**：真实 E2E 没打通线上模型（本机没有 `TEXT_LLM_*` 配置、按纪律也不该有
   生产凭证）。提示词的实际效果需要一次联通联调；单测里覆盖的是"拿到模型结果之后的确定性逻辑"。
