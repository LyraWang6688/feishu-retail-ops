三个子命令：

| 命令 | 干什么 |

| `node scripts/e2e-run.mjs return ...` | 真跑一条退货 + 打印验收对照 |

## 二、长连接：本地能不能收事件？

### 结论（一句话）

**长连接本身能连上（用现有凭证在本地实测连接稳定），但用现有凭证收不到任何事件 —— 缺的不是"长连接"，而是这个应用的权限；要本地收事件，必须有一个独立的"测试应用"（业务负责人的想法是对的），并给它开云文档事件订阅权限。**

### 实测 1：长连接能建立 ✅

用现有凭证（`cli_aa3341b397389cd4`）在本机跑 `server/scripts/ws-listen.mjs`
（用 SDK 自带的 `@larksuiteoapi/node-sdk` 的 `WSClient`，只连、不处理、不写任何表）：

```
✅ 长连接已建立（2026-10-05T16:19:04Z）
…状态 {"state":"connected"}  × 7 次心跳（50s / 75s 两次试连都稳定）
```

### 实测 2：但一条事件都收不到 ❌

在长连接**开着的时候**，我往测试 Base 真写了一条记录（「其他配品」表 `reczz28JnCahLMLn`，
2026-10-06 00:19:22），那个表**不在**采购分派表里，所以没有任何业务副作用。结果：

```
这段时间收到事件：0 条
```

### 为什么收不到（实测到的硬条件）

飞书的「表记录变更事件」不是配了事件订阅就会推的，还要**应用订阅到具体这张表**：

```
POST /open-apis/drive/v1/files/{file_token}/subscribe?file_type=bitable
```

我用现有凭证去调这一步，飞书直接拒绝：

```
99991672 Access denied. One of the following scopes is required:
[drive:drive, docs:doc, sheets:spreadsheet, docs:event:subscribe]
应用尚未开通所需的应用身份权限
```

→ **没有订阅权限 ⇒ 这个应用的任何传输方式（webhook 也一样）都收不到表变更事件。**
顺带发现同一个应用还缺两个权限（都实测到了）：

| 缺什么 | 表现 | 影响 |
| --- | --- | --- |
| `docs:event:subscribe` / `drive:drive` | 订阅表事件 99991672 | 收不到表变更事件 |
| `im:resource:upload` / `im:resource` | 上传图片 99991672 | 真发退货单图会失败（本次被脚本拦住了，没外发） |
| `drive:drive` / `docs:document.media:upload` | 写附件 400 Access denied | 退货单图写不回「单据信息」附件（见 ⑤） |

### 「webhook 和长连接能不能同时用」——**我没能核实**（如实说）

- 本机网络取不到飞书官方文档（网页抓取被网络环境挡住），飞书开放平台后台我也没有入口，
  **所以我不能下"能并存/不能并存"的结论**。
- 我能确定的两件事：
  1. SDK 自带文档写明：「长连接为**集群模式、不支持广播**：同一应用部署多个客户端时，只有随机一个客户端会收到」；
     「长连接仅支持事件订阅，不支持回调订阅」；
  2. 本机实测：长连接**能连上但收不到事件**；且这 50/75 秒里它 **0 条事件 → 没有抢到任何线上事件**。
- 因此**"要不要新建测试应用"的答案是：要**，但理由不是靠猜"二选一"，而是：
  就算两种方式能并存，也必须有一个**有事件订阅权限 + 图片上传权限**的应用给本地用；
  把这个测试应用单独配成长连接，线上那个应用一个字都不用改。

### 万一将来两边都收到同一条事件（会重复处理）——**有解 ✅**

只处理 **`file_token == 测试 Base`** 的事件即可。事件里带 `file_token`（线上代码本来就这么过滤的，
见 `server/src/routes/larkEvents.js:108`：`if (fileToken !== ownAppToken) return {}`）。
测试 Base 与生产 Base 的 app_token 不同，天然隔离。

### 需要什么条件（照做清单）

1. **新建一个测试应用**（或给现有测试应用加权限），至少开通：
   `docs:event:subscribe`（或 `drive:drive`）＋ `bitable:app` ＋ `im:resource:upload`；
2. 用这个应用对**测试 Base** 调一次订阅（脚本已写好：`server/scripts/ws-subscribe.cjs`；
   现有应用调这一步就是 99991672，所以必须换应用/加权限）；
3. 在应用后台把**事件订阅方式设为长连接**（只影响这个测试应用，线上不受影响）；
4. 本机挂 `node scripts/ws-listen.mjs --seconds 600`，就能一直收；
   想验证"真的能收"，另开一个终端跑 `node scripts/ws-poke-event.cjs` 造一条事件。

- 采购行为的两种写法都能被识别成退货：`采购退单/PURCHASE_RETURN`（运行 C）和

### 【结论】**业务主链路达标**；有两个"没达标"项，都不是退货链路本身的毛病

1. **② 是我的验收标准写错了**，不是代码错了。
   实现口径是「**一个尺码一行，变动数量 = 该尺码退掉的双数**」：
   - 2 双落在 2 个尺码 → 2 行 × 1（运行 B、C ✅ 字面也成立）
   - 2 双同一个尺码 → 1 行 × 2（运行 A、首跑）
   这**不是退货链路特有**：库存单测里「采购入库 2 双」就是这个口径 —— 实时库存 2 行（一双一行）、
   库存流水 1 行、`变动数量 = 2`（`server/test/inventoryMvp.test.js` 的
   `purchase adds one live record per pair`）。
   **建议改法**（不用改代码）：把验收标准②从"新增 N 行"改成
   **"「库存流水」变动数量合计 = N（一行一个尺码），行为 = 采购减少 / STOCK_PURCHASE_DECREASE"**。
   如果业务上真的要"一双一行"，那是另一个需求（要改 `InventoryService.executeOperation`，
   会同时影响销售、采购入库），**需要业务负责人拍板**。

2. **⑤ 的"图写回附件"没达标，因为本机这个应用没有云文档上传权限**（400 Access denied）。
   代码路径是通的（单测覆盖、日志里能看到它走到了上传这一步）。补权限即可。
   另外"真发到群 + @人"必须用有 `im:resource:upload` 权限的应用才能验证。

## 四、跑之前发现、并且必须说的一个环境缺口

测试 Base 的「行为管理」里**原本没有** `STOCK_PURCHASE_DECREASE`（采购减少）这一行，
而 `InventoryService.resolveStockBehavior` 要求"**有且只有一条**该编码、库存方向=减少、已启用"。
→ **不补这一行，退货链路必然在"扣库存"这一步失败**（报错文案：
`行为管理中编码为「STOCK_PURCHASE_DECREASE」的行为必须且只能有一条记录，请先在行为管理表补齐`）。

我按授权在**测试 Base** 补了一行（`reczz28Jn7SBKCdm`，名称「采购减少」，方向=减少，已启用；
脚本里就是 `e2e-run.mjs setup` 干的事）。

⚠️ **由此引出一个需要业务负责人确认的线上风险**：本机凭证**读不到生产 Base**（403 / code 91403），
所以我**无法核实生产 Base 的「行为管理」里有没有这一行**。请她在生产 Base 的「行为管理」里确认：
**编码 = `STOCK_PURCHASE_DECREASE`、名称「采购减少」（或「采购退货」）、库存方向 = 减少、已启用，且只有一条**。
没有的话，线上退货也会卡在扣库存这一步。

4. **真实外发到群 + @人**：没验证（应用缺图片上传权限，我按"能拦就拦"拦住了）。
   文字里的 `@` 语法是代码里既有的写法，真机未验证。
5. **一个顺带发现（读代码发现，不是本次跑出来的）**：退货分流用的正则是
   `/退货|return|STOCK_PURCHASE_DECREASE/i`，所以「**销售退货 / SALE_RETURN**」也会被判成"采购退货"。
   测试 Base 的「行为管理」里就有这条记录。挂在「供应商对接」的采购行为上时，两者都能正常分流成退货；
   但如果哪天有人把「销售退货」错挂上去，会被当成采购退货扣库存。风险低，但值得记一笔。
6. 本次没验证「采购申请」（报货）那条链路，只验证了退货；报货链路的入口脚本同样可直接调
   （`handleReportBatch` / `processSupplierReport`），需要的话可以扩展 `e2e-run.mjs`。
