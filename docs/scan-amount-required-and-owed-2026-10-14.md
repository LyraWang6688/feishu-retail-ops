## 一、她的两条裁决（逐字 · 最新权威）

```
①「**销售货品页的每件金额必须填，只有资金页可以不填**」
②「**只要本次付的金额小于累计的，那么差额都是未收款，包括本次付款为 0**」
```

**准确边界**（不要把两条混成一条）：

| | 管什么 | 结论 |
| --- | --- | --- |
| 裁决 ① | **每件实收金额**（货品页那一列） | 空 ⇒ **400 + 人话 + 零写入**（只看页面这条路由 ✓ **服务层不动** ✓） |
| 裁决 ① | **整单收款明细**（资金页） | **仍然可以全空** ✓ ——「先记成待补充、之后去工作台补收款」那条老路**保留** ✓ |
| 裁决 ② | 差额 | `累计 − 本次已收` **> 0** ⇒ **一律**补一条【未收款】· **不看档位** · **0 收款也补** |
| 裁决 ② | 边界 | `累计 = 0`（什么都没填 / 没单价）⇒ 差额 0 ⇒ **仍然是 0 条**（不许写出"金额 0"的【未收款】） |

## 三、顺带修掉的一个真 bug（在翻新哨兵时撞出来的）

`server/src/routes/scanPage.js` 里，资金页拦住时取人话的那一行是：

```js
return t[`${settlement.code}Body`] || t[settlement.code] || '';   // ✗
```

而 `settlement.code` 是 **snake_case**（`full_without_money` / `partial_amount_missing` /
`partial_amount_mismatch`），配置里的文案 key 是 **camelCase**（`fullWithoutMoneyBody` …）
⇒ 那三条 block 的**人话一直渲染成空串**：她看到的只有一个干巴巴的 400 + 满页表单。

⭐ 这正是她 2026-10-14 真机「点了 6 次『提交整单付款』都只看到 400」的现场之一
（当时日志里连原因都没有，页面上也没有一句话 —— **两处都静默**）。

已修：先做 snake_case → camelCase 再取真源文案（**不新编中文** ✓ 仍只用既有模板 ✓）。
⚠️ 这条修复**不是本题范围之外的自选动作**：`AC-E2E-11` 原来那句
`assert.match(html, /全付/)` 是**空断言**（这一页本身就有「全付」单选项，正则永远为真，
根本测不到"有没有人话"）—— 把它改成**钉住人话那一段**（`data-view="payment-step-notice"`）
之后，不修这个 bug 就过不去。**判据是收紧的，不是放宽的。**
