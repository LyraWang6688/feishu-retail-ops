# 配品销售 → S交易明细：把飞书工作流搬进代码（2026-11-17）

> 业务负责人：把飞书工作流「配品销售同步」（wkfJ6Uo7GihkbmGF）变成代码逻辑：
> 监控「配品销售」新增记录 → 同步到「S交易明细」。

## 一、原工作流（只读核对）

- 触发：配品销售 AddRecordTrigger；条件 名称 / 数量 非空；watched field 金额。
- 动作：S交易明细新增一条：
  - 支付方式 ← 配品销售.收款方式
  - 收支方向 = 收入
  - 交易金额 ← 配品销售.金额
  - 钱款状态 = 已收款
  - 收付日 ← 触发记录创建时间

## 二、代码版映射

| S交易明细 | 取值 |
| --- | --- |
| 支付方式 | ← 配品销售.收款方式（关联） |
| 收支方向 | 收入（固定） |
| 交易金额 | ← 配品销售.金额（要求 > 0） |
| 钱款状态 | 已收款（固定） |
| 收付日 | ← 配品销售记录的 created_time（拿不到才用处理时刻） |
| 交易明细ID | PX-<配品销售 record_id>（新增：幂等键 + 可追溯） |
| 关联销售单 | 不写（配品销售不关联销售单） |

代码比工作流多两条防错账：

1. **幂等**：按交易明细ID 先回查，已有就跳过；事件重投/重复执行不会重复记账。
2. **不写 0 元**：金额缺失/<=0 跳过并告警；工作流只要求名称/数量，金额空也会记一笔。

## 三、触发与配置

- 事件：drive.file.bitable_record_changed_v1，按 FEISHU_V1_ACCESSORY_SALE_TABLE_ID 分派；
- 只认 record_added；编辑/删除不补记；
- 代码：server/src/services/accessorySaleSyncService.js；
- 配置：server/src/config/accessorySaleSync.js；
- **不设开关**：配了源表 ID，代码就一直同步（业务负责人 2026-11-17 定）。
