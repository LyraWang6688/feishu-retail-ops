# 「字符串手术」的工程教训（2026-10-13）

> 一句话结论：**字符串手术必须带断言 + 立刻 `require`**。
> 这条不是理论 —— 2026-10-12/13 把「采购退货告知」的多行拼接从服务里搬进 config，**连挂三次**，
> 四个坑**全是靠"捕获断言"和"改完立刻 `require`"当场抓住的**，每次都能干净还原、零损失。

## 一、做了什么（背景）

把 `purchaseWebhookService.js` 里的用户可见文案搬进 `config/purchaseWebhookTexts.js`（技术债：只挪位置，**一个字符不许改**）。
难点不是"搬"，而是**这几段是"多行多字面量拼接"**，例如：

```js
return `采购退货没处理：${label}${sizeNames ? `（${sizeNames}）` : ''}在实时库存里一双都没有，` +
  '我没有扣库存，也没有把这条记录标成已处理。库存补上之后再提交一条退货记录就好～';
```

## 二、四轮踩坑 → 最后的防法（**这张表就是本文的价值**）

| 轮次 | 症状（怎么发现的） | 根因 | 最后采用的防法 |
| --- | --- | --- | --- |
| 第 1 次 | 服务 `SyntaxError: Unexpected token '...'` | **按"子串"替换**多行表达式：只换了表达式、没换**整个 arrow 体** ⇒ 括号失衡 | ⭐ **整块替换**：用**平衡括号**算出精确区间，整段一起换 |
| 第 2 次 | 替换后语义错、`require` 报错 | 用 `text.index('return ')` 找锚点 ⇒ **抓到全文第一个 `return`**（不是目标那句） | ⭐ **锚点限定作用域**：先切出目标函数体，只在**函数体内**定位 |
| 第 3 次 | config 里 `=> return …` ⇒ `SyntaxError` | 捕获时把 `return ` 关键字**一起切进了表达式** | ⭐ **捕获必带断言** + 捕获时**剥掉 `return `**（`+ len('return ')`） |
| 第 3 次（同轮） | `Cannot read properties of undefined (reading 'unknownItem')` | ① `config` 的 `module.exports` **没加新组** ② 服务的解构行**没加新名字** ③ 替换时空位写成了 `return return …`（**双 return**） | ⭐ **每次替换都 `assert` 命中** + ⭐ **改完立刻 `require`** |

## 三、可复用的五条（照做即可）

1. **捕获必带断言**：抓完第一件事是证明"抓对了" ——
   例：`assert '采购退货没处理' in zero_expr`、`assert label_lit == "'这个货品'"`、`assert src.count(lit) == 1`（唯一性）。
2. **锚点限定作用域**：绝不在全文 `index(...)`；先切出函数体/语句块，再在块内定位。
3. **整块替换**：多行表达式（`a + b`、arrow 体、`return … ;`）一律按**平衡括号**算区间，**整段替换**；**不要**改写成模板串（那等于改行为）。
4. **每次替换都 `assert`**：`assert s.count(old) == 1`（或 `== n`）；**没断言过的替换不算做过**。
5. **改完立刻 `require`（或跑一个最小真调用）**：语法/引用类错误**当场**就暴露，不用等测试；
   本批四个坑里，**两个是 `require` 抓的、两个是捕获断言抓的**。

## 四、一条标准管线（下次照抄）

```
① 切作用域（函数体/语句块）→ ② 捕获 + 逐条断言"抓对了/唯一" → ③ 生成 config（常量 + 填参函数，零逻辑）
→ ④ 整块替换（平衡括号、后→前）+ 每次 assert → ⑤ 立刻 require + 一次最小真调用
→ ⑥ 参数契约 AC（config 形参名 === 调用点 key 名）→ ⑦ 服务级端到端 AC（真调、断言整句）
→ ⑧ 白名单用项目扫描器重生成（不手改）→ ⑨ 全量 + 真启动
```

## 五、两条配套经验

- **参数只取 `${}` 的根标识符**：`${plan.batch_no}` 的根是 `plan`（不是 `plan`+`batch_no`）。
  半截标识符当参数 ⇒ 调用处变成"引用不存在的局部变量" ⇒ 运行时 `ReferenceError`（本批真踩过）。
  ⇒ 用**参数契约 AC**（形参名 === 调用点 key 名）钉死；**局部函数**（如 `sizeText`）就**当参数传进去**。
- **端到端 AC 在核事实，不是走过场**：本批它抓到我把文案记错了（以为「**要我**一起退」，实际是「**要**一起退」）。
  ⇒ 断言时**只钉"本轮抽走的那几处真的被用上"**，不要写死"整句开头"（那些字面量本轮没抽、将来会变）。

## 六、失败之后怎么收（也很重要）

三次失败都做到：**不用 `checkout`/`stash`**，而是
① 用**自己刚生成的 config 里存着的原文**反向还原；② 残下的文件按**明确路径** `git show HEAD:<path> > <path>`；
③ 复核 `git status` 干净 + 目标测试绿。⇒ **零损失、可继续**。

（本文只记**手法**，不记业务口径。）
