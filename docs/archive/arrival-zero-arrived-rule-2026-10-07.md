# 口径：到货核对里「某个尺码实际到 0 双」是**正常情况**

> 业务负责人 2026-10-07 当面拍板（逐字）：
> 「**这个情况是正常的！对啊，所以这就是为什么要到货核实啊，如果我们报的货都到了，
>  还用校准这个差异吗？如果这个尺码算下来为 0，那么就不用入库啊！**」

## 规则

1. **差异算出来 `实际 = 0 双` 的明细行 → 该行【不入库】**（不写库存流水），
   **但不阻断整单**：其它 `实际 > 0` 的行照常入库。
2. **「实际到 0 双」不是错误** —— 它是到货核实的**正常结果**（供应商漏发一整双）。
   ⚠️ 因此**不应**回「对不上明细，先不入库」那类话术；应正常出**核对卡片**，
   并在卡片上如实显示该行「申请 N 双 → 实际 0 双（未到）」。
3. **真正的「对不上明细」**（她说的货号/尺码在单据里找不到 / 模型没解析出可对应条目）
   仍然走原来的 `unmatched` 路径（回一句让她重说）—— **两者不许混为一谈**。
4. **「单据信息」（代码里 `purchaseRequest`）表一个字都不改** ——
   到货差异**只体现在库存流水**，不回写申请单（这是既有口径）。
5. 入库数量 = **实际数量**（不是差异数）。

## 起因（真实事故，今天真机）

```
她：8230黑色少一双38码 / 93827黑色少39 40码各一双
而这三行在「单据信息」里【申请数量各 1 双】⇒ 实际 = 0 双
→ 15:00:03 日志 purchase.arrival.reconcile.plan_unmatched reason:"actual_not_positive"
→ 机器人回「我没把你说的话对上这批采购申请的明细，先不入库」← 对她来说是**误报**
```
根因：代码把「实际到 0 双」当成不合法（源自另一条口径「实际到货不会为 0」）。
她已明确纠正：**0 双是正常的**。

## ⚠️ 与旧口径的关系

2026-10-06 她说过「实际到货不会为 0」——**本条是对它的收窄/修正**：
「0 双」在**单行**上是允许的（那行不入库）；该旧说法**不再**用于否掉整单。
