# 工程教训（2026-10-12 起，逐条追加）

## 8. ⭐ 「捕获」是最危险的步骤：抓完必须先**断言抓对了**（2026-10-12，实测两次失败）

**事故**：把 `purchaseWebhookService` 里两段**多行字符串拼接**抽进 config 时，用脚本"捕获原文 ⇒ 整块替换"。
两次失败，各自的根因不同：

| 次数 | 做对了什么 | 错在哪 |
|---|---|---|
| 第 1 次 | 整块替换的方向是对的 ✓ | 按**子串**替换表达式、没换**整个 arrow** ⇒ 留下 `...surpluses.map((entry) => (` 这种**括号失衡**行 ⇒ `SyntaxError` |
| 第 2 次 | 改用**平衡括号整块替换** ✓ | **捕获步骤**写成 `text.index('return ')` ⇒ 抓到的是**整个文件里第一个 `return `** ✗（征兆：打印出的 `roots` 是空的、连 `${}` 都没有） |

**两次都被 `node -e "require('./src/services/...')"` 当场抓住**（没有流到测试阶段）✓ · 两次都**干净还原**（`git show HEAD:`
显式路径逐文件还原，**没用** `checkout .` / `stash`）⇒ **零损失** ✓

⭐ **教训（可复用）**：
1. **捕获之后立刻断言**："这段就是我想要的那段" —— 例如 `assert '采购退货没处理' in expr`；
   **只打印不算断言** ✗（第 2 次就是因为"看到了征兆却没断言"）。
2. **锚点要限定作用域**：先切出目标函数体，再在里面找锚点；**绝不**在全文里 `index('return ')` ✗。
3. **改完立刻 `require` 一次**（本文件里两次事故都是靠它第一时间发现的 ✓）——比等测试快得多。
4. **多行表达式不按子串改** ✗ ⇒ 要么整块（平衡括号）替换，要么按行区间重建。
5. **失败后干净还原**（显式路径 `git show HEAD:` ⇒ 逐文件还原）⇒ 不留半成品 ✓（这两次都做到了 ✓）
