# 一处事实：每一步写什么（业务负责人 2026-10-17 逐字拍板）

> 背景：2026-10-17 凌晨，业务负责人对「货 / 钱各写什么」给了**逐字口径**，并明确
> 「**扣库存要从资金页那一跑挪到货那一跑**」。按《协作纪律》第 3 条「约定必须落文件」，特此单独立档。

## 1. 业务负责人原话（逐字 · 2026-10-17）

> 「**对啊，扣库存就是要从资金页那一排挪到货啊，不是都说了吗？**」

> 「**货影响的就是销售主表和销售明细；如果是现货的话，影响的还是实时库存和库存流水。
>  资金页就只是影响一个销售明细呀，就是这样子的呀。**」

> 「**那好吧，那这样子我们的资金页面就不用加待办了，它必须得把这一次付款填写的信息给填完，明白了吗？**」

## 2. 结论（三块 · 可照做）

### 2.1 「货」那一跑（她点「成交」那一刻）
- **销售主表**（含「总金额」= 一单里每一双实收累加）
- **销售明细**（每一双一行）
- ⭐ **如果是现货 ⇒ 还要**：**扣「实时库存」＋ 写「库存流水」**
- 🔴 **不写收款明细**（钱那一半留给资金页）

### 2.2 资金页
- ⭐ **只写「收款明细」这一类**（即销售明细里的收款那一半）
- 🔴 **必须把这次付款的信息填完** —— **不许空着提交**
  - ⚠️ 这与 `docs/scan-money-split-async-race-2026-10-16.md` 时代的「资金页可以空着 ⇒ 直接成单」**相反**
  - ⇒ **既有判据里钉「资金全空也能成单」的那些，要按本条迁移**

### 2.3 待办口径
- 🔴 **不加**「资金未写入」这条待办（她说「**不用加待办了**」）
  - 因为资金页**必须填完**，不存在「没填就溜走」的单
  - ⇒ 原先那个顾虑（"货出了钱没收 ⇒ 待办里看不见"）**不再成立**

## 3b. 「资金页没有跳过」＋「订单列表没有补充信息单」（2026-10-17 追加 · 逐字）

> 「那这样子，我们的资金页面上是不是有"跳过"？」
> 「**就没有"跳过"了，它就是"提交"。他提交的这个资金，就是他在交货的时候，
>  或者说在第一次交易的时候付款的金额。**」
> 「**如果他的金额小于总金额，那要不然就是未付，要不然就是部分付，那就是需要进行二次交付的情况。
>  所以说，我们的销售订单列表里面，已经没有"我要再补充信息"这个选项了。**」

### 结论
1. 🔴 **资金页上没有「跳过」** —— 只有「提交」
   - ⚠️ **现状相反**：\`config/scanWrite.js:15\` 逐字「⑤ 钱可以先不填（"先货后钱"）：货照记」；
     \`:125\` 逐字「未付（**默认档**，2026-10-11 晚起）：**一个字都不用填** —— 收款行可以空着」
   - ⇒ **要改成：必须填完才能提交**
2. ⭐ **提交的金额 = 他交货时（或第一次交易时）付的钱**
3. ⭐ **金额 < 总金额** ⇒ 落在「未付」或「部分付」⇒ **属于"需要二次交付"的单**
4. 🔴 **销售订单列表里【没有】「我要再补充信息」这个选项了**
   - 现状：\`server/public/workbench/config/orders.js:124\` 有
     \`{ key: 'supplement', label: '补充信息单', tag: '待补充', tone: 'warning' }\`
