>  **现货待收款**的是**收款明细**里**未收款且交易类型是现货**的记录，说明里是 货号 颜色 尺码 还需要加上待收的金额；

>  **右栏**是用户的**确认按钮**，点击之后这笔待平台结算就会**变为已收款**；
>  而**采购**就是报货批次数据**到货状态为未到货**的记录，这里的文字说明，包括**供应商和创建时间以及报货数量**」
>
> 补充口径（同日）：
> · 「抖音团购券是从收款明细里的**创建时间**开始算，比如创建时间是 1001，那么就是 1006 应该 1001 维度下的所有待平台结算的总额，
>   然后用户点了按钮之后，就会把这些记录状态的收款状态改为**已收款**，同时更新收款明细里的**收款时间**；
>   团购券那笔的金额用券的**「平台结算款」**」
> · 标题 = **【团购券待结算】**；按钮文案 = **「确认到账」**

## 一、四个区域（顺序 = 配置顺序）

| 区域 | 数据源与筛选 | 每行两类内容 |
| --- | --- | --- |
| **【预定】** | 「销售明细」里 **履约状态 = 未交付** 的记录 | 文字 = 货号 + 颜色 + 尺码 + **该销售单号的待收款** ｜ 「查看话题」按钮 |
| **【现货待收】** | 「收款明细」里 **收款状态 = 未收款** **且** **交易类型 = 现货** | 文字 = 货号 + 颜色 + 尺码 + 待收金额 ｜ 「查看话题」按钮 |
| **【团购券待结算】** | 「收款明细」里 **收款状态 = 待平台结算** | 左栏 = 按**核销日**（= 收款明细的**创建时间**，上海自然日）分组的**待结算总额**；**到账日 = 核销日 + 5 个自然日** ｜ 右栏 = **「确认到账」**按钮 |
| **【采购】未到货的报货批次** | 「报货批次」里 **到货状态 = 未到货** | 文字 = **供应商 + 报货日（创建时间）+ 录入数量** ｜ 「查看话题」按钮 |

## 二、团购券那块的金额怎么取（2026-10-08 实测确认）

- 金额口径（她的）：**券的「平台结算款」**。
- 定位链路：收款明细.**交易方式**（关联「收款方式管理.收款方式」，名字里带价，如 `抖音代金券（89.9）`）
  → 按名字里的价匹配「团购券管理.**售价**」→ 取该券的**平台结算款**（89.9 → 85.4；49.9 → 47.4）。
- ⚠️ 解析不到券时**退回「收款金额」**并记一条日志（**不静默**、也不编数）。
- 实测：`XSD-20260927-0143`｜交易方式 `抖音代金券（89.9）`｜收款金额 85.4｜券表结算款 85.4 ⇒ 一致（她当天已把这条改对）。

## 三、三个「先按这个做」的默认（她没反对就照此实现）

1. **逾期**：显示 **到账日 ≤ 今天** 的全部（不只"今天正好该到账"），并标 **「逾期 N 天」**。
   理由：现存那笔核销日 09-27 ⇒ 到账日 **10-02**，只显示"今天该到账"会让它**再也不会出现**（漏账）。
2. **「确认到账」的语义**：把那**一批**（同一个核销日）的全部「待平台结算」→ **已收款**，
   并写 **「收款时间」= 点击那一刻**；**幂等**（点两次不重复写）；只在**群**里可用（沿用私聊已移除的口径）。
3. **一单多件**：【预定】按**明细逐件一行**（她说的是"销售明细里的记录"）；
   【现货待收】按**收款明细**一行，文字里并列它关联销售单的货号/颜色/尺码。
