# 派活纪律：子智能体 vs 队友（业务负责人 2026-10-16 明确 · 两次）

## 她的原话（逐字）
> 「**一次性的任务你交给子智能体，固定长期项目你交给你的队友**，你推进的真是太慢了」
> 「你发现你等子智能体的时间太长了吗？我发现你有的任务都停滞了，等他回复都等了 10 分钟。
>  **你要记住：你交给子智能体只能是一些零碎、一次性的活儿，长期性的你必须得交给你的队友**」

## 规矩（可执行）
| 活的性质 | 交给谁 | 为什么 |
|---|---|---|
| ⭐ **零碎、一次性**（跑一遍验证 / 改一处文档 / 清目录 / 查一个数） | ⭐ **子智能体（`subagent`）** | 干完就散，不需要再对话 |
| ⭐ **长期、多轮、要跟进**（一条链的实现与收尾、要反复核证据、要纠偏） | ⭐ **队友（`spawn_teammate` 出来的）** | ⭐ **可以 `send_message` 收发消息、问进度、纠偏、按需再派** ✓ |

## 🔴 为什么（今晚的真实教训）
- ⭐ 我把**长期**的活（异步＋成功页极简／五处扫一扫统一／销售扫码）交给了**子智能体** ✗
  ⇒ ⭐ **收不到消息** ✗ **看不到进度** ✗ **卡住了只能干等** ✗（`async-success` 卡 8 分钟；有的任务停滞 10 分钟 ✗）
- ⭐ 还因此出过一次**两个写入者撞同一张卡**：⭐ 那个"卡住"的子智能体**其实活着**，在同一个 worktree 里提交了 `a41816c` ✗
  ⇒ ⭐ 队友建目录时没看到它 ⇒ 两边重叠 ✗（队友处置正确：导出自己的改动 ＋ 还原他的 commit ✓ 各写各的目录 ✓）
- ⭐ 队友**可以收发消息** ⇒ ⭐ 能问"你到哪一步了"、能纠偏、能拿到中期回报 ⇒ ⭐ **不会停滞** ✓

## 落地（Lead 每次派活前自问一句）
⭐ **"这件事要跟我来回几轮吗？"**
- ⭐ **要** ⇒ ⭐ **队友** ✓（并在派活书里写清交付物与判据 ✓）
- ⭐ **不要**（一次就完）⇒ ⭐ **子智能体** ✓
⚠️ **队友名额有限（8 个）** ⇒ ⭐ 一次最多派到满；⭐ 空闲队友**优先复用**（唤醒）而不是新建 ✓

## ⭐ 名额只有 8 个 ⇒ **优先复用旧队友，不要新建**（业务负责人 2026-10-16 明确）

> 她的原话：「**对呀，你的队友名额就是 8 个呀，你复用原来的不就行了吗？
>  只要他的上下文就可以复用原来的呀**」

- ⭐ **队友上限 = 8** ⇒ 满了再 `spawn_teammate` 会直接 **报错**（`Team member limit 8 reached`）。
- ⭐ **正确做法**：⭐ **`send_message` 唤醒一个空闲旧队友** ✓ ——
  ⭐ **它之前的上下文（工作区路径、分支、判据、纪律）还在** ✓ ⇒ 接手更快 ✓ **不需要新建** ✗
- ⚠️ **`send_message` 对一个"上一轮已结束"的队友 = 开始新的一轮** ✓（`inactive` 只表示"当前没有回合在跑" ✓ 不代表它死了 ✓）
- ⭐ **自检**：「我要派的这件活，**能不能交给某个已经在跑的/刚结束的队友**？」
  ⇒ ⭐ **能就别新建** ✗（新建还占名额 ✓）
- ⭐ **实例（2026-10-16 22:2x）**：队列里 8 个满 ⇒ 我**复用了刚交完 `#776` 的 `async-final`** ✓
  让它接「删存草稿」那张做了一半的卡 ✓ **它立刻就接着干了** ✓（不用重建上下文 ✓）

## 🔴 测试 Base 必须【串行】：同一时刻只许一个 agent 跑"带 `.env` 的全量"（2026-10-16 实测教训）

- ⭐ **实测事实**：`small-batch` 用 `.env` 软链跑全量 ⇒ ⭐ **把真测试 Base 的活体 E2E
  （`test/scanMoneyPageTwoStepVerify.test.js`）跑起来了** ✗ ⇒ ⭐ **3 条红**（`entry 590 vs 589` 这类**计数差**）
  ⇒ ⭐ 根因 = ⭐ **另一个 agent 同时在写【同一张测试 Base】** ✗ ⇒ ⭐ **不是代码 bug** ✓
- ⭐ **口径**：⭐ **带 `.env` 的全量会写测试 Base 的 `entry/detail/payment/ledger` 并断言真实行数增量** ✗
  ⇒ ⭐ **两个 agent 同时跑 ⇒ 行数互相干扰 ⇒ 假红** ✗
- ⭐ **纪律**：
  1. ⭐ **同一时刻只许一个 agent 跑"带 `.env` 的全量"** ✓（⭐ 跑之前先问 Lead / 在群里说一声 ✓）
  2. ⭐ 别人要核 ⇒ ⭐ **跑"不带 `.env`"的** ✓（⭐ 那 4 条活体 E2E 按 CI 口径 **skip** ✓ 与 CI 同口径 ✓）
  3. ⭐ **出现"计数差"型红（`X vs X-1`）⇒ 先怀疑并发，不是先怀疑代码** ✓
- ⚠️ ⭐ 这不是"禁止跑" ✗ —— ⭐ 是**要串行** ✓
