## 一、三种「明细 ID」的格式与位置（她逐字确认）

| 字段 | 格式 | 位置 | 说明 |
| --- | --- | --- | --- |
| **销售明细ID** | `{销售单号}-{两位序号}` 例 `XSD-20261012-001-01` | **销售明细**行 | "一单有多笔销售时，按主表销售单号再拆成子单" |
| **收款明细ID** | `{销售单号}-收款-{两位序号}` 例 `XSD-20261012-001-收款-01` | **收款明细**行 | "一单有多种收款方式时拆收款子单" |
| **采购明细ID** | `{报货批次号}-{两位序号}` 例 `CGD-20261012-0001-01` | **采购明细**行 | "同一个报货批次号里面，这是我的第几双鞋" |

- 主表只存**单号/批次号**（销售主表存销售单号 · 采购主表存报货批次号）；ID **都写在明细行上**（她原话）。
- ⭐ **【未收款】占位行也占一个号**（她原话：「收款明细里那条【未收款】占位行也算一个号」）⇒ 占位行 = `-收款-01`，之后每笔真实收款接 02、03…
- ⭐ **后补一行 ⇒ 接着排号，不重排已有行**（旧行的号一字不变）。
- **幂等重放不重复占号**。
- 号在**写库之前**取 ⇒ 若某次写入最终失败，**可能出现空档**，但**绝不重号**（取舍：空档可接受、重号不可接受）。
- 超过 99 ⇒ `-100`（补零不截断，**有意如此**）。
- **并发**：靠既有串行（扫码按 openId、工作台补款有队列、售后按指纹幂等）⇒ 同一单被两个入口同时写的**极小撞号窗口**已知、**本轮不加按单锁**。
- ⭐⭐ **2026-10-12 她定：老单不补号**（上线前建的旧行保持空号；新行从 01 起）⇒ **不做回填脚本**。

- 生产真表（只读核过 `property`）：`type=18 ui_type=SingleLink` ＋ ⭐ **`property.multiple = true`**（关联「行为管理」`tblbTvUT4AFsCK4K`）。
- ⇒ 全现货 ⇒ `[现货]` · 全预订 ⇒ `[预订]` · ⭐ **混合单 ⇒ `[现货, 预订]`**（去重、按明细首次出现顺序）。

## 四、销售主表四个状态字段 = 四条进度线（代码现状）

| 字段 | 值域 | 谁写 · 何时 |
| --- | --- | --- |
| **确认状态** | 未确认 / 已确认 / 已取消 / 待修改 | 扫码建单先写「未确认」⇒ 提交这一单时写「已确认」 |
| **销售状态** | 未写入 / 部分写入 / 已写入 / 写入失败 | 建单先「未写入」⇒ 销售明细写完后「已写入」 |
| **资金状态** | 未写入 / 已写入 / 写入失败 | 收款行写完后「已写入」（= "账做完了"的判据） |
| **库存状态** | 未写入 / 部分写入 / 已写入 / 写入失败 | 交付扣库存后写；售后改库存也会写 |

- ⚠️ 硬边界：**状态列写失败绝不影响业务写入**（只记 warning）。取值与字段名都在 `config/salesStatusDimensions.js`（配置先行）。
