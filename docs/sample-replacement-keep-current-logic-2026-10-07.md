# 口径：补样品（门盒转样品）**保持现状，不修**

> 业务负责人 2026-10-07 原话（逐字）：
> 「**不用修，我觉得现在的逻辑挺好的～**」

## 背景（她真机遇到的现象 + 我们的分析）

2026-10-07 那笔销售（`XSD-20261007-0007`）里：她一单同时卖了 **40 码（展示样品）与 41 码（门盒）**，
然后在确认卡片上选「用 **41 码**门盒补样品」。结果：
```
16:04:39  warn  lark.sales.sample_replacement.apply_failed
          error:「41码已没有门盒库存，请重新选择」
```
原因：**41 码刚被这一单自己卖掉**，门盒已空 ⇒ 补样品失败 ⇒ 系统**再发一张「请补选展示样品」卡片**
（列出仍有门盒的 38/39/43/44/45）。她随后选 **43 码** → 成功：
```
16:10:56  写「库存流水」KC-20261007-0476（库存行为=门盒转样品 · 尺码 43 · 变动数量 0）
16:10:58  inventory.sample.promoted { size:43, ledger_record_id:... }
16:10:59  卡片更新成终态
          「实时库存」26802-6|黑|A|43 的「所属状态」由 门盒 → 样品
```
（「变动数量 0」是**对的**：同一行内 门盒 −1、样品 +1，净变化为 0。）

## 我们提过、她**决定不做**的两处「改进」

1. ~~补样品可选项改成在**扣完本次销售库存之后**再算~~（避免给出"马上会被这一单卖掉"的选项）
2. ~~失败时把**原因**告诉她~~（"41码刚被这单卖掉，没门盒了，请重选"），而不是默默再发一张卡

⇒ **两处都不做**：她认为**现在的逻辑挺好**（失败后重发一张可选卡片 = 她实际可用的流程）。

## ⚠️ 边界（以后别当成 bug 再提）

- 补样品**失败后重发一张卡** = **有意行为**，不是 bug。
- 失败原因**只写在日志**（`lark.sales.sample_replacement.apply_failed`）= **当前口径**。
- 若将来要改成"先算后选"或"失败说明原因"，**必须先问她**（本文件记录了她 2026-10-07 的相反决定）。
