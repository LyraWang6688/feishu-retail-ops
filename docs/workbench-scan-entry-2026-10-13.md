# 工作台里加「扫一扫」直接进扫码页（业务负责人 2026-10-13 提问）

> 她的原话（逐字）：
> 「**工作台可以进入到扫码页吗？**这个可以做到吗？即点击**扫一扫**就是当前的扫码页～」

## 一、结论：**可以做到** ✓（技术上没有障碍）
工作台（`GET /workbench`）与扫码页（`/s/<编号>`、`/r/<recordId>`）**都是同一域名下的网页** ✓
⇒ 在工作台里放一个「扫一扫」入口、打开扫码页 = **同域跳转** ✓（没有任何跨站/权限问题 ✓）

## 二、三种做法（按体验从好到差）
| 方案 | 做法 | 代价 / 前提 |
|---|---|---|
| **A（体验最好）** 飞书原生扫码 | 用飞书 H5 JSAPI 的扫码能力（`biz.util.scanCard` / `scanCode` 一类）⇒ 拿到结果直接跳扫码页对应记录 ✓ | ⚠️ 需要**配置 JSAPI 签名**（`jssdk` ticket + 当前 URL 签名 ✓）—— 项目目前**没有**这套（要新增 ✓） |
| **B（自控）** 页内摄像头 + JS 二维码库 | 「扫一扫」按钮 ⇒ `getUserMedia` 起摄像头 ⇒ 前端解码二维码 ⇒ 跳扫码页 ✓ | ⚠️ 需引入一个**二维码解码库**（新增依赖 ✓）· 需 H5 可信域名 + 摄像头授权 ✓ · 首次可能较慢 ✓ |
| **C（最省）** 只做"进扫码页" | 「扫一扫」= 一个**链接**，进到**销售首页 `/s`**（不带编号 ✓ 页面里已有「请扫下一个标签」指引 ✓） | 她仍需用**飞书自己的扫一扫**去扫标签 ✗（不是"页内扫" ✗） |

⭐ 建议：**先 C（立刻可用、零风险 ✓）**，同时排 **A**（体验最好，但要先配 JSAPI 签名 ✓）
—— ⚠️ 若她要在**工作台的验收 tab 里直接扫**（验收产品标签 ✓）⇒ 必须 **A 或 B** ✓（不能只靠 C ✗）

## 三、与"验收迁到工作台"的关系（重要）
- 验收迁到工作台后，**在验收 tab 里"扫一双"** 就依赖本页的扫码能力 ⇒ 那时 **A/B 是必需** ✓ 不是可选 ✓
- ⚠️ 因此顺序建议：**先定 A 还是 B** ⇒ 再动手做"验收 tab"（否则验收 tab 里没有可用的输入方式 ✗）
- ⚠️ 她先前那句"扫码页不也是网页吗"已确认：**webview 里摄像头是可能可用的** ✓ ⇒ 但 **必须真机验一次** ✓（B 的前提 ✓）

## 四、需要她/后端定的
1. 选 **A（飞书原生扫）** 还是 **B（页内摄像头）**？（A 需新增 JSAPI 签名能力 ✓）
2. 「扫一扫」放在**工作台哪个位置**？（一级按钮 / 采购-验收 tab 内 / 首页 ✓）
3. 扫到**产品标签**时：直接进"该编号的扫码页"✓ 还是进"工作台的验收录入"（带该编号预填 ✓）

## 五、AC 草案（先写先红）
- `工作台出现"扫一扫"入口；点击 ⇒ 打开扫码页（同域跳转 ✓ 200/302 ✓）`
- `扫到的编号/记录 ID ⇒ 落到对应页面（该编号预填 ✓ 不经过中转页 ✗）`
- `未授权摄像头 / 非飞书环境 ⇒ 明确人话兜底（手输编号 ✓ 不许白屏 ✗）`
- `扫码页 / 工作台**整页只有一段脚本**的既有约束不被破坏 ✓`（各自页内 ✓）
