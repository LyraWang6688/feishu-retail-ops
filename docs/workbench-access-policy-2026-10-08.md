# 工作台准入口径（业务负责人 2026-10-08 定）

## 结论：**白名单保持为空 = 有意为之**

> 她的原话：「这没问题，我们现在就是一个小的限制：**只要是在这个租户里面就可以打开**」

- `WORKBENCH_ALLOWED_OPEN_IDS` **留空** ⇒ 飞书租户内**任何能通过飞书登录的人**都能打开工作台（含扫码页）。
- **不是漏配、不是待办** —— 是当前有意的准入口径（小店、人少、都是自己人）。
- 代码语义（`requireWorkbenchAccess`）：未启用认证 **503** / 未登录 **401** / **白名单外 403**；
  ⚠️ **空 ≠ 拒绝全部**，空 = 不限制（这条已在既有用例里钉住）。

## ⚠️ 什么时候必须重新考虑

1. 租户里加入了**外部人员**（供应商、兼职、临时工）之后 —— 他们登录后**也能扫码建单/补货/验收**；
2. 需要**"只读的人"**（只能看库存、不能动数据）—— 现在只有"能进 / 不能进"一档，
   细粒度权限是**另一件事**（要做才做，别默认存在）。

## 真要收紧时的操作路径（留给将来的自己）

1. 让要放行的人**各登录一次工作台**；
2. 从 `GET /api/auth/feishu/me`（或访问日志）取他们**在本应用下的 `open_id`**
   （⚠️ open_id **按应用隔离**：不能用别的应用的 open_id）；
3. 写进线上 `.env` 的 `WORKBENCH_ALLOWED_OPEN_IDS`（逗号分隔）→ **重启**；
4. 复核：名单内的人应 **200**、名单外的人应 **403**（不是 500、不是静默放行）。
