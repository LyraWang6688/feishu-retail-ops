# 资金页两刀 · 第二刀的**硬约束**（业务负责人原话，逐字）

> 她的原话：
> 「**实时库存减少，还需要经过销售主表、销售明细以及实时库存还有库存流水，才能真的减少啊**」
>
> 意思（按代码核过 ✓）：
> · 库存**真的减少** = 那一串写入**全部完成**之后：
>   **销售主表（建单）→ 销售明细 → 实时库存 → 库存流水** ✓
> · ⇒ ⚠️ **不是"点了提交就减"** ✗ 也**不是"页面一出来就减"** ✗

## 一、对【第一刀】（资金页前置）——**不变** ✓
点**资金页按钮** ⇒ 才 `submitSale`（建单 + 明细 + 库存 + 交付 **全部同步跑完**才回成功页 ✓）
⇒ 第一刀上线后：「**看到成功页 = 库存已经真的减了**」✓（与今天一致 ✓）
🔴 **第一刀里不要动 `scanWriteService.js` 的写入顺序** ✗（保持"同步写完整串再回页" ✓ 风险最小 ✓）

## 二、对【第二刀】（异步切点）——**硬约束** ✗
单号一出就回成功页 ⇒ 那一刻 **明细 / 库存 / 流水可能还没写完** ✗ ⇒ 必须做到：

1. ⭐ 成功页文案**不许**写"已完成 / 已扣库存"✗
   ⇒ 只能：「**本单已创建（单号），正在写入明细与库存**」✓
2. ⭐ 主表状态**如实**：明细/库存/交付未完成前停在「**未写入 / 部分写入**」✓；完成才「已写入」✓；
   失败 ⇒ 「**写入失败**」✓（⚠️ **不许新造"未完成"选项** ✗ —— 值域只用 `config/salesStatusDimensions.js` 里已拍板的 ✓）
3. ⭐ 工作台那一行要能看出"**货 / 钱 / 库存各到哪一步**"✓ ⇒ 没写完 ⇒ 显示「**未完成，可点重试**」✓
4. ⭐ **AC（能真红 ✓，第二刀必须写）**：
   · `成功页返回的那一刻 ⇒ 实时库存**尚未**减少（或与实际一致 ✓）`
   · `后台写完 ⇒ 实时库存**真的减少** + **库存流水**有那一条` ✓
   · `后台失败 ⇒ 实时库存**不许**凭空减少` ✓（**不许假成功** ✗）
5. ⭐ **幂等**：重试**只走 `submitSale`（同一 `submitKey`）** ✓
   ⇒ AB：`同键两跑 ⇒ 库存只扣一次` ✓（**能真红** ✓）
   🔴 **绝不**直调 `salesOrderService._confirm`（它开头**没有跳过判据** ⇒ 会重复写 / 重复扣 ✓）
