# 验收整体移到工作台（采购 → 子 tab）；扫码页不再做验收（业务负责人 2026-10-13 裁定）

> 她的原话（逐字）：
> 「另外**验收我们整体移到工作台的采购里**，开一个**子 tab，做验收**，
>  **扫码页，不需要验收了**～，以及是否可以在扫码页，**直接做一个 tab 页**呢，
>  这样也可以**直接跳转到工作台**～」

## 一、裁定
1. 🔴 **扫码页不再有"验收"入口**（`accept` 领域 / `allowAccept` / 验收路径在扫码页上整体退场 ✗）
2. ⭐ **验收移到工作台**：工作台「采购」下新增**子 tab = 验收** ✓
   · 内容 = 现有验收能力（**未到货批次列表 → 选批次 → 逐码/逐双录入 → 提交**）✓
   · 落点/服务层**一行不改**（`scanArrivalService` / `purchaseArrivalConversationService` /
     `purchasePendingBatchService` / 库存与幂等 ✓）—— **只换入口与页面** ✓
3. ⭐ **扫码页加一个"去工作台"的 tab/入口** ✓（可直接跳转到工作台 ✓）

## 二、必须保持不变的（红线，与《销售流程》那份同源）
- 验收的**写入链路**：幂等（`submit_key`）· 「到货状态 = 已到货」判据 · 库存与流水 · 顺序 · 串行队列 ✗
- 「未到货批次列表」的定义 · 验收后离开列表 · 失败不写 ✗
- 昨天刚做的**验收提速**（批量写 31→5 调用 · `/accept` 短缓存 ✓）—— **继续有效** ✓（它作用于服务层 ✓）
- `v1BitableSchema` / 表结构 ✗

## 三、待她拍的三个细节（不可自行决定）
1. **工作台上的验收怎么输入？**
   · 工作台（飞书网页）通常**拿不到摄像头** ✗ ⇒ 大概率是「**选批次 + 手输编号/尺码 + 点选**」✓
   · 若她仍要"扫码"⇒ 需要走"扫码页跳到工作台对应批次"这条路（把扫码结果带过去 ✓）
2. **扫码页 → 工作台**的跳转方式：
   · 飞书内**新窗口/侧边栏打开工作台**（AppLink ✓ 见 AGENTS 第 13 条）✓
   · 或**本页内嵌**（体验连贯但受 H5 安全域名与鉴权限制 ✓）
3. 工作台「采购」子 tab 的**命名与顺序**（例：采购申请 / 报货批次 / **验收** ✓）

## 四、AC 草案（先写先红）
- `扫码页不再出现"验收"入口/字样`（渲染 + 源码双哨兵 ✓）
- `扫码页出现"去工作台"入口，且目标可用（跳转 200/302 ✓）`
- `工作台采购下出现"验收"子 tab；未到货批次列表可见（同一批 record_id 集合 ✓）`
- `通过工作台提交一次验收 ⇒ 结果与"扫码页验收"逐字相同（到货状态 + 库存 + 流水 ✓ 回归）`
- `扫码页那条旧的验收路径已下线（回归哨兵：不再可达 ✓）`
