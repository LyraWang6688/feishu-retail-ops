### 关键的三个"唯一真源"（**已经是收敛的，不是四处各写一份**）

2. **页面上有哪几列**：`config/scanPage.js:91-96` 的 `STATES`
   ```js

   ```
3. **空状态列是服务层按配置追加的**：`services/scanPageService.js:1283-1284`

   const emptyStateRows = stateCounts.get('') || 0;

它既不在 `SELLABLE_STATES`（⇒ 三个 tab 当它不存在），又被库存页当合法的一列计入 `共 N 双`。

## 3. 「未标状态」到底是什么 —— **是空值（脏数据），不是合法在库状态**

证据（全部只读）：

| # | 证据 | 结论 |
| --- | --- | --- |
| 1 | `config/scanPage.js:86-96`：`STATES.columns = ['门盒','样品','仓库']`；文档 `docs/inventory-adjustment-plan-2026-10-06.md:79`：实时库存「所属状态(单选 **门盒/样品/仓库**)」 | 她的数据模型里**只有三个状态**，没有"未标" |
| 2 | `services/inventoryService.js:142` `LIVE_STATES = ['门盒','样品','仓库']`；`:621 / :896 / :1133` 三处 `if (!LIVE_STATES.includes(state)) throw` | **代码写不出空状态**（唯一写库存的 service 会当场抛错）⇒ 空值只可能是**人直接在表里改出来的**（或历史遗留行） |
| 3 | `config/scanPage.js:87-89` 注释「数据里出现配置外的取值**不丢、不猜**，按原值追加一列并记 warn —— 否则"共 N 双"会与明细对不上」 | 追加这一列是**工程上的不丢数据**，**不是业务口径**（`unknownStateNote` 也写着"不在预期取值里"） |
| 4 | `services/labelPrintService.js:586-596` 注释：「所属状态为空的那条**仍然是"入库过"的行**，只是不参与标签」 | 它是一种**"有行、但状态无从得知"**的记录：**实物大概率在**，但**不知道是门盒/样品/仓库** ⇒ 既不能算可卖、也不能算仓库 |

⇒ **它是脏数据（或残缺数据），不是合法的第四种在库状态。**
⇒ 但**它确实占着一双鞋**（她的表里那条记录就是 1 双）—— 所以
「库存页把它算进共 N 双」与「三个 tab 不认它」**都各有各的道理**，
**这就是必须由她拍的那一条口径**。

## 4. 到底哪个页面算错了？—— **"口径不一致"成立，"某页写错"不成立**

- **三个 tab（销售 / 补货 / 退货）没有算错**：它们按她 2026-10-09 定的
  「可卖 = 样品 + 门盒」（`docs/scan-selling-caliber-2026-10-09.md`）算，空状态**不属于**这两个状态
  ⇒ 判"不可卖"是**忠于她口径**的。
- **库存页也没有算错**：它显示的是"这一款在库里有多少条记录"，并对配置外/空状态
  **不丢、不猜、单列一列**（否则"共 N 双"与明细对不上）。
- **错的是"两套口径同时出现在同一个扫码页上，而页面不解释"** ⇒ 她看到的是"同一双鞋两个数"。

⚠️ 唯一可以叫"错"的地方（**取决于她怎么拍**）：
- 若「未标状态」**该算有货** ⇒ **销售 / 补货 / 退货三页都错**（把一双能卖的鞋当成了没有）。
- 若「未标状态」**不该算**（脏数据）⇒ **库存页那句「共 1 双」是错的**
  （它把脏数据算进了总数，且**没有任何提示告诉她"这 1 双不算库存"**）。

## 5. 两条修法（**都收敛到一处配置**）—— 请她拍

### A. 若「未标状态」**应该算有货**
- 一处配置：把「未标」登记进**可卖状态清单**（`SELLABLE_STATES` 由硬编码改为读
  `config/scanPage.js` 的 `STATES`，新增一个语义键，例如 `sellableStates: ['门盒','样品','<空>']`）；
- 三个 tab **自动全部跟着变**（它们共用 `sellableCountOf` / `purchaseSizeLines`），
  **不需要在四个地方各改一遍**；
- ⚠️ 连带影响（必须一起说清）：销售提交时**这一款会被记成「现货」**（`SALE_CASH`），
  退货页会允许退这一双，补货页会把它当"有货"不预勾。

### B. 若「未标状态」**不该算**（= 脏数据，**我倾向这条**）
- 一处配置：把「空/配置外状态」的**显示口径**登记进配置（例如
  `STATES.sellableColumns: ['门盒','样品']` ＋ `STATES.nonSellableNote`），
  让**库存页标题与备注对她把话说清**，例如：
  - 标题拆开：「**可卖 0 双** · 另有 1 双状态未标注（不算可卖）」；
  - 备注固定一句：「有 1 双的「所属状态」是空的，**不算可卖**，请去「实时库存」补状态」；
- 三个 tab **一个字都不用改**（它们本来就是对的）；
- ⚠️ **她的盲区也顺带被解决**：那 1 双不是"没了"，而是"需要她去表里补一个状态"。
