# 扫码页（标签二维码）的访问控制 —— 2026-10-11 实测结论

**背景**：业务负责人问「任何人扫到这个二维码，是不是都需要经过飞书验证？不在这个租户里的人点开显示什么？」
—— 下面每条都是**在公网匿名实测**或**核代码**得到的，不是推断。

## 一、实测（公网、未登录）

```bash
curl -sS -o /dev/null -w "%{http_code} ⇒ %{redirect_url}" \
  "https://hm.bamamei.online/s/93827%7C%E9%BB%91%E8%89%B2%7CA"
# ⇒ 302 ⇒ https://hm.bamamei.online/api/auth/feishu/start?next=%2Fs%2F93827%257C...
```

⇒ **扫码页不是公开页面**：匿名访问一律 **302 跳到飞书登录**，`next=` 会带回原地址。

## 二、三类人分别看到什么（业务负责人当晚自己复验过，一致）

| 谁 | 结果 |
| --- | --- |
| **自己人**（飞书登录后 + 在名单里） | 正常扫码页：库存 / 尺码 / 打印 / 建单 ✓ |
| **不在租户里的人**（码被外人扫到） | 飞书先要求登录 ⇒ 登不进去 ⇒ 看到**飞书的提示页**（「你不是该组织的成员 / 无权访问」）⇒ **看不到货品、库存、价格**，也**动不了数据** ✓ |
| **在租户里但不在白名单** | 同样进不去（白名单 `WORKBENCH_ALLOWED_OPEN_IDS`，只有名单里的人能进）✓ |

## 三、另外两道闸门（同一条链路上的其他入口）

| 入口 | 闸门 |
| --- | --- |
| 工作台 `/workbench`、`/api/workbench/*` | 飞书登录（`LARK_WEB_AUTH_ENABLED`）+ 白名单 |
| 电脑侧打印接口 `/api/label-print/*` | **设备令牌**（`LABEL_PRINT_DEVICE_TOKEN`，缺/错 ⇒ 401；未配 ⇒ 503） |
| 其余 `/api/*` | `x-api-key`（`API_KEY`） |

## 四、Nginx 侧

`server/ops/nginx/snippets` 的白名单是**路径白名单**（`location ^~ /s/`、`^~ /api/`、`^~ /workbench/`），
**没有 IP 限制、没有 basic auth** ⇒ 访问控制**全部由应用层（飞书登录 + 白名单 + 令牌）负责**：
```nginx
location ^~ /s/ { proxy_pass http://127.0.0.1:5000; ... }
```
⇒ 因此「扫码页安全」这件事**依赖应用层的登录闸门**，不能靠 nginx。

## 五、结论

⭐ **标签二维码 = 只有自己人（且在白名单里）能用**；外人扫到只能看到飞书的登录/无权限提示，
**既看不到数据、也做不了操作** ✓ —— 这条已由业务负责人 2026-10-11 真机复验确认。
