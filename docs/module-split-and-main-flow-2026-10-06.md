# 主链路与板块划分（业务负责人 2026-10-06 逐字确认）

> 她的原话：「**因为后续就不用私聊了，后续就是在群聊里面沟通销售、采购的事情。**」

## 一、两个板块的职责

### 【工作台】= 看 + 摆弄（**不录入业务**）
| 项 | 形态 |
| --- | --- |
| 查询功能 | 工作台自己的页面（销售查询 / 实时库存） |
| 库存调整 | 工作台自己的页面（盘点调整 / 换季调整） |
| **采购申请** | ⭐ **多维表格表单链接**（`…/share/base/form/shrcnn4f9ZJzpm7JbT2rCH247xc`）—— **她填的** |
| **退货申请** | ⭐ **多维表格表单链接**（`…/share/base/form/shrcnjsqt4D5URseSSXgecYlqGd`）—— **她填的** |

⭐ 她明确：「**工作台里面的采购和退货申请，就是我们填的那个多维表格的链接**」
（代码 `server/public/workbench/config/links.js` 里就是这么做的，注释也写明是**外链**。）

### 【群聊（与机器人交互）】= 说 + 办
| 项 | 状态 |
| --- | --- |
| **初次销售** | ✅ 已做（主群说一笔 → 建记录 + 开话题 + 回卡片） |
| **售后** | ✅ 已做（退货/换货，回复回话题） |
| **二次交付** | ✅ 已做（"收到微信 500" → 更新那笔） |
| **采购到货情况** | ✅ 已做（人在图下开话题，回复回话题） |

＋ **私聊后续【不用了】** —— 见 `docs/channel-decoupling-2026-10-06.md`。

## 二、创建话题【只有两个入口】
1. ⭐ **初次销售**：群里说一笔 → 建销售记录 + **在【那条消息】下开话题** + 回卡片
2. ⭐ **采购申请单（图）发到群**：**人（她或采购的人）在图片下【手动开话题】** → 机器人在话题里回复
   - 🔴 **退货申请单**也发到群，但**没有后续链路** → **不开话题**

## 三、话题里的回复（就这两类）
- **采购端**：回复**到货情况**
- **销售端**：回复**售后（是否需要退换货）** + **预付 / 未付情况下的二次交付确认**

## 四、主群准入 —— 她 2026-10-06 确认「**这样可以**」
- 🔴 **主群里【不 @机器人】**，机器人靠**正文像不像销售**自己判：
  - **像** → 处理，回卡片
  - **不像** → **完全不搭理**（群里日常聊天绝不能被触发）
- **误判的兜底**：会建一张**卡片**，她点「**取消**」就行 —— **不会直接写数据**。
- ⚠️ **现状**：主群**必须 @ 机器人**才处理（`LARK_BOT_OPEN_ID` 判据）→ **这条要改**。

## 五、其他已确认的口径
- **被换过的那双可以再退** —— 她：「**不会啊，没有这些规定啊！**」→ **不做限制**。
- **卡片点按钮后不需要额外弹私聊文字** —— 她：「**我们的消息卡片会变化啊！**」
  → 卡片更新本身就是反馈；**那条多余的私聊 toast 要去掉**。
