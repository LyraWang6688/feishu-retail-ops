# 零售数智经营助手

面向线下零售与小型企业的飞书数智经营底座。邯美当前部署名称为“邯美数智经营工作台”，代码仓库名为 `feishu-retail-ops`。系统基于豆包大模型、飞书机器人和飞书多维表格运行；当前 V1 以飞书私聊机器人为主入口，微信小程序已冻结，暂时保留但不再新增功能。

## 1. 项目简介
系统通过飞书私聊接收销售文字和采购到货图片，调用豆包模型解析，经用户确认后写入飞书多维表格，并联动销售/采购明细、库存流水、实时库存、资金流水和供应商往来款。后续网页工作台复用相同业务层，不另写一套入账逻辑。

当前功能状态、已确认决策和后续路线统一记录在 [项目进展与迭代路线](docs/project-progress.md)。当前暂不接入微信支付、支付宝或抖音支付 API；销售的商品与资金信息由用户一并提供。用户可以使用飞书会话内置的语音转文字能力，项目后端只接收并处理最终文字，不另建音频转写链路。

原微信小程序代码暂时保留在 `miniprogram/`，但已进入冻结状态。服务器可通过 `ENABLE_LEGACY_WECHAT=false` 停用全部旧接口；飞书链路不依赖该目录或遗留路由。

## 2. 核心功能
- **销售私聊录入**：自然语言解析、缺失字段提示、确认卡片和正式入账。
- **采购到货录入**：多图按私聊用户归集、图片识别、确认入库。
- **库存联动**：库存流水是变更凭证，实时库存保存“编号＋尺码”的最新数量。
- **资金联动**：销售确认形成收入；采购入库形成应付，实际付款才形成资金支出。
- **配置引用**：货品、供应商、收款方式和行为从配置表关联，不在业务表重复维护。
- **遗留兼容**：旧微信识别、同步和查询 API 由单独开关控制，不参与飞书 V1 的业务依赖。

## 3. 技术栈
- **交互入口**：飞书机器人私聊；后续增加飞书网页工作台
- **遗留前端**：微信小程序原生代码（冻结）
- **后端**：Node.js + Express
- **部署方式**：腾讯云轻量应用服务器 + Nginx + PM2
- **AI 模型**：豆包 (Doubao) 大模型 API
- **表格服务**：飞书多维表格 (Feishu Bitable) API

## 5. 快速开始
1. 安装依赖并启动后端
   - `cd server && pnpm install`
   - `pnpm run dev`
2. 飞书事件订阅接口为 `/api/lark/events`，销售和采购通过飞书机器人私聊录入。
3. 生产环境默认后端地址为 `https://api.bamamei.online`。
4. 轻量云服务器部署（服务器目录暂时保留兼容名称）
   - 服务器安装 `Node 20`、`pnpm`、`pm2`、`nginx`
   - `cd /opt/box2bitable/server && pnpm install`
   - `pm2 start ecosystem.config.js`
   - `nginx` 反向代理到 `127.0.0.1:5000`
   - `certbot --nginx -d api.bamamei.online`
5. 遗留微信小程序本地调试建议
   - 勾选“**不校验合法域名、web-view（业务域名）、TLS版本以及HTTPS证书**”
6. 飞书图片写入排查（可选）
   - 设置 `FEISHU_DEBUG=true` 输出飞书上传与写入的入参/出参日志（token 默认脱敏）
   - 设置 `FEISHU_DEBUG_SHOW_TOKENS=true` 输出 token 明文（仅建议本地排查使用）
