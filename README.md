# 零售数智经营助手

面向线下零售与小型企业的飞书数智经营底座。邯美当前部署名称为“邯美数智经营工作台”，代码仓库名为 `feishu-retail-ops`。系统基于豆包大模型、飞书机器人和飞书多维表格运行；当前 V1 以飞书私聊机器人（销售录入）、飞书多维表格记录变更事件（供应商报单 → 采购申请）与飞书网页工作台为正式入口，原微信小程序链路已于 2026-10-01 正式退役并从代码库移除。

## 1. 项目简介
系统通过飞书私聊接收销售文字；采购由「供应商报单」记录变更触发，解析「数量说明」后免确认直接生成采购申请（不再经过确认卡片）。销售部分经用户确认后写入飞书多维表格。销售、采购、库存和收款分别由业务模块负责；网页工作台处理销售订单的后续收款与交付。

当前功能状态、已确认决策和后续路线统一记录在 [项目进展与迭代路线](docs/project-progress.md)。当前暂不接入微信支付、支付宝或抖音支付 API；销售的商品与资金信息由用户一并提供。用户可以使用飞书会话内置的语音转文字能力，项目后端只接收并处理最终文字，不另建音频转写链路。

仓库级智能代理入口是 [AGENTS.md](AGENTS.md)；每份文档的现行 / 历史状态见 [文档索引](docs/README.md)。

原微信小程序链路（`miniprogram/`、`/api/recognition`、`/api/sync`、`/api/query`、`/api/analytics`、`/api/sales/tasks`）已于 2026-10-01 正式退役并整体删除，代码中不再有任何开关可以重新启用它。退役记录见 [Legacy WeChat Retirement](docs/archive/legacy-wechat-retirement.md)。

## 2. 核心功能
- **销售私聊录入**：自然语言解析、缺失字段提示、确认卡片和正式入账。
- **采购报单录入**：供应商报单记录新增时按「报货批次号」归批，解析「数量说明」免确认生成采购申请，并按供应商出图发回。
  （「采购到货」表仍在，但**拍照识别链路已于 2026-10-05 退场**，新增记录不触发任何事，只作数据容器：到货日 / 验收原话 / 确认状态 / 验收人 / 图片。）
- **库存联动**：交付和采购入库触发库存流水；实时库存每条记录代表一双鞋，按“编号＋尺码＋所属状态”操作。
- **收款记录**：同一销售单可关联多笔收款；补尾款只新增收款记录，不影响库存。
- **配置引用**：货品、供应商、收款方式和行为从配置表关联，不在业务表重复维护。

## 3. 技术栈
- **交互入口**：
  - 飞书机器人私聊：销售自然语言录入
  - 飞书多维表格记录变更事件：供应商报单（文字 → 采购申请，到货记录新增不再触发任何事）
  - 飞书网页工作台（已实现）：销售订单后续收款、交付与工作台查询
- **后端**：Node.js + Express
- **部署方式**：腾讯云轻量应用服务器 + Nginx + PM2
- **AI 模型**：豆包 (Doubao) 大模型 API
- **表格服务**：飞书多维表格 (Feishu Bitable) API

## 5. 快速开始
1. 安装依赖并启动后端
   - `cd server && pnpm install`
   - `pnpm run dev`
2. 飞书事件订阅接口为 `/api/lark/events`：销售通过飞书机器人私聊文字录入，采购由「供应商报单」记录变更事件触发（采购到货记录的新增/修改**不再触发**任何链路）。
3. 生产环境默认后端地址为 `https://api.bamamei.online`。
4. 轻量云服务器部署（服务器目录与 PM2 进程名暂时保留兼容名称，见 [飞书 V1 运行与排查](docs/feishu-v1-operations.md)）
   - 服务器安装 `Node 20`、`pnpm`、`pm2`、`nginx`
   - `cd /opt/box2bitable/server && pnpm install`
   - `pm2 start ecosystem.config.js`
   - `nginx` 反向代理到 `127.0.0.1:5000`
   - `certbot --nginx -d api.bamamei.online`
5. 日志排查（可选）
   - 后端日志是结构化 JSON（`server/src/utils/logger.js`），飞书写入事件形如 `bitable.record.created`；可按事件名过滤 PM2 日志
